# Web HMI 产品意见

> 评审日期：2026-08-14  
> 评审范围：整机浏览、印刷单元详情、报警处理、锁定标记、检测窗编辑、页面跳转及 1920×1080 / 1280×720 屏幕适配  
> 评审方式：实际运行页面、逐步操作主流程、模拟多报警和信号异常，并结合当前前端状态逻辑进行检查  
> 口径说明：本文为产品评审记录；与《产品计划》的最终交互和范围规则冲突时，以《产品计划》和当前实际实现为准。

## 一、总体结论

当前版本在 1920×1080 分辨率下已经具备较成熟的工业 HMI 视觉基础：整机状态、报警、速度、印刷单元和操作区域的信息层级较清楚，暗色主题、状态颜色和实时数据表达也符合工业控制场景。

但现阶段仍有若干会影响操作安全、状态可信度和任务闭环的问题。作为演示原型可以继续使用；如果准备进入现场试用，应优先修复以下四项阻断问题：

1. Enter 键可能在非编辑场景下直接保存检测窗草稿。
2. 多报警在 1280×720 下会超出报警抽屉，底部报警无法查看和处理。
3. 未确认或待复位的报警可能被顶部状态显示为“正常”。
4. 普通查看印刷单元会自动生成检测窗草稿，导致只读操作产生脏数据。

当前阶段评价：

| 维度 | 评价 | 说明 |
| --- | ---: | --- |
| 1920×1080 页面展示 | 8/10 | 信息完整、层级清楚，适合作为主要设计基准 |
| 1280×720 页面适配 | 6/10 | 基本可用，但关键动作隐藏、多报警不可达、页签文字拥挤 |
| 任务流程闭环 | 6/10 | 主路径已形成，但状态同步、草稿和报警定位仍不完整 |
| 工业操作安全性 | 4/10 | 存在误保存、报警弱化、正式参数即时写入等风险 |

| 优先级 | 问题 | 主要风险 | 建议方向 |

## 三、详细问题与解决方案

### 1. Enter 键可能直接保存检测窗草稿

**问题表现**

锁定标记页注册了全局键盘监听。只要页面存在草稿，在页面任意位置按 Enter 都可能触发保存，不要求光标位于编辑区域，也不要求当前处于明确的编辑状态。

实测中，PU8 页签从“草稿”直接变为“已设窗”，操作过程中没有点击“确认保存”。

**风险**

- 操作员按 Enter 激活其他按钮时，可能同时保存检测窗。
- 维护人员使用键盘巡检时容易产生非预期参数变更。
- 保存结果缺乏明确的操作归因，不利于审计和追溯。

**解决方案**

1. 仅在 `editing === true` 且检测窗编辑区域获得焦点时响应 Enter。
2. 当焦点位于按钮、链接或表单控件上时，不执行全局保存快捷键。
3. Enter 只提交“当前编辑动作”，不能自动把新建草稿写入正式窗口。
4. 新建或替换检测窗必须通过可见的“应用检测窗”按钮完成。
5. 保存成功后展示包含 PU、坐标和时间的明确反馈，例如：`PU8 检测窗已应用 · x 171–291 · 16:24:30`。

**验收标准**

- 在页面空白处、导航栏和任意普通按钮上按 Enter，草稿状态不发生变化。
- 只有进入检测窗编辑态后，快捷键提示才出现。
- 保存前后状态可明确区分为“编辑中”“有未应用修改”“已应用”。

### 2. 多报警时底部报警不可达

**问题表现**

报警抽屉使用固定高度，但报警列表没有独立的纵向滚动机制。1280×720 下模拟 6 条报警后：

- 抽屉可视高度约为 720px；
- 实际内容高度约为 811px；
- 最后两条报警超出屏幕，无法查看和操作。

**风险**

- 新报警可能被排在不可见区域。
- 操作员无法完成确认或复位，直接影响报警闭环。
- 报警数量增加后，问题会持续放大。

**解决方案**

1. 报警抽屉改为纵向 Flex 布局。
2. 抽屉标题和整机启动区固定在顶部。
3. 报警列表设置 `flex: 1; min-height: 0; overflow-y: auto;`。
4. 在列表顶部显示数量和筛选项：全部、活动、待确认、待复位。
5. 有新增报警时保留当前位置，并以醒目标记提示“新增 1 条”，避免列表自动跳动导致误点。

**验收标准**

- 1280×720 下展示 20 条报警时，所有报警均可滚动到达。
- 抽屉标题、关闭按钮和报警数量始终可见。
- 抽屉滚动不带动背景页面。

### 3. 未完成报警可能显示为“正常”

**问题表现**

顶部“最高报警”主要根据当前活动报警计算。当报警条件已经恢复，但仍处于待确认或待复位状态时，顶部可能显示绿色“正常”，同时又显示“0 活动 · 4 待确认”。

这两个信息在语义上相互冲突：设备可能已恢复，但报警处理流程尚未完成。

**风险**

- 操作员容易把“当前条件已恢复”理解为“报警已经处理完成”。
- 停机报警未复位时，红色风险提示过早消失。
- 顶部状态与报警抽屉中的实际状态不一致，降低系统可信度。

**解决方案**

建立明确的报警生命周期：

1. 活动 / 待确认；
2. 活动 / 已确认；
3. 已恢复 / 待确认；
4. 已恢复 / 待复位；
5. 已复位 / 已关闭；
6. 已归档。

顶部状态建议使用以下优先级：

1. 存在活动停机报警：红色“停机级报警”；
2. 存在已恢复但待复位的停机报警：红色或红色锁存“待复位”；
3. 存在活动警告：黄色“活动警告”；
4. 存在待确认报警：黄色“存在待处理报警”；
5. 所有报警完成闭环：绿色“正常”。

顶部统计建议改为：`3 活动 · 2 待确认 · 1 待复位`，不要把所有未确认状态混为一个数字。

**验收标准**

- 只要存在待确认或待复位报警，顶部不得显示绿色“正常”。
- 同一条报警在顶部、单元状态带和报警抽屉中的状态一致。
- 停机报警完成复位前，其锁存标识始终可见。

### 4. “仅报警”会隐藏仍需处理的单元

**问题表现**

“仅报警”当前只筛选 `alarmState !== normal` 的单元。报警条件恢复后，单元可能恢复为普通状态颜色，但其停机报警仍处于待确认或待复位阶段，因此会从“仅报警”列表消失。

**解决方案**

将筛选语义从“当前正在报警”调整为“当前需要关注”：

- 活动报警；
- 待确认报警；
- 待复位报警；
- 数据中断；
- 被报警联锁停止；
- 启动条件不满足。

筛选名称建议由“仅报警”改为“需处理”，另外提供“活动报警”作为更窄的筛选项。

**验收标准**

- PU7 报警恢复但未复位时，仍显示在“需处理”列表中。
- 列表项直接展示阻塞原因，如“待复位”“信号中断”“联锁停止”。

### 5. 普通查看动作会自动生成检测窗草稿

**问题表现**

在整机页面选中 PU7 查看单元详情后，系统会自动生成默认检测窗草稿，并提示用户保存。此时用户尚未进入锁定标记页，也没有表达创建检测窗的意图。

**风险**

- 只读查看产生了可编辑状态和脏数据。
- 多次查看不同 PU 后，会出现多个用户并未主动创建的草稿。
- 操作员难以判断哪些草稿是真实配置任务，哪些是系统自动产生。

**解决方案**

1. 选中单元、查看详情和打开曲线都必须保持只读。
2. 只有用户点击“新建检测窗”或“重新创建检测窗”后，才创建草稿。
3. 没有检测窗时，曲线页展示空态和单一主动作：`新建检测窗`。
4. 系统可以提供推荐区域，但应先显示“建议检测区域”，用户确认后才转为草稿。

**验收标准**

- 在整机页连续查看所有 PU，不产生任何检测窗草稿。
- 打开没有检测窗的曲线页时，不自动进入编辑状态。
- 草稿必须能够追溯到一次明确的用户操作。

### 6. 检测窗调整会直接修改正式值

**问题表现**

已有检测窗在拖动、缩放或使用“检测窗左移/右移”时，会直接修改正式窗口数据。页面缺少持续可见的“未应用修改”状态，也没有统一的应用和取消入口。

**风险**

- 触摸误操作立即影响偏差计算。
- 用户离开页面时无法判断修改是否已经生效。
- 不同调整方式的行为不一致：新建有草稿，已有窗口调整却直接提交。

**解决方案**

统一使用事务式编辑模型：

1. 点击“编辑检测窗”；
2. 复制正式窗口生成编辑草稿；
3. 所有拖动、方向按钮和尺寸调整只修改草稿；
4. 右侧固定展示“应用修改”和“取消修改”；
5. 离开页面或切换 PU 时，如果存在未应用修改，弹出明确提示；
6. 应用后记录操作人、时间、旧值和新值。

**验收标准**

- 调整过程中正式检测窗和偏差计算规则不变，除非产品明确选择“草稿预览计算”。
- 点击取消后完整恢复编辑前坐标。
- 未应用修改切换页面时不会静默丢失或静默提交。

### 7. PU 切换、URL 和来源提示不一致

**问题表现**

从 `PU7` 检测页切换到 `PU8` 后：

- 页面内容显示 PU8；
- URL 仍可能保持 `?pu=PU7`；
- 刷新后会重新回到 PU7；
- “已从整机 PU8 进入”会随着当前选中 PU 变化，错误地把当前对象当成来源对象。

**解决方案**

1. 切换 PU 时立即同步 URL 查询参数。
2. 将 `sourceStationId` 和 `selectedStationId` 分开管理。
3. “已从整机 PU7 进入”只描述进入来源，不随检测页内部切换改变。
4. 如果用户直接通过侧边栏进入，不显示“已从整机进入”，改为“当前查看 PU2”。
5. 当前版本返回整机时清除 PU 和报警定位上下文，恢复整线摘要；如果后续产品需要保留当前 PU，应另行确认，不在本版本默认启用。

**验收标准**

- 切换到 PU8 后，URL 同步为 `?pu=PU8`。
- 刷新页面后仍停留在 PU8。
- 来源提示与真实进入路径一致。
- 浏览器前进、后退或页面返回按钮的结果可预测。

### 8. 1280×720 下关键操作隐藏过深

**问题表现**

在 1280×720 下：

- 整机详情面板可视高度约 391px，实际内容接近 797px；
- 锁定标记右侧面板可视高度约 309px，实际内容接近 627px；
- “确认保存”“取消草稿”等关键动作位于面板下方；
- 滚动提示不明显；
- PU 页签中的“未设窗”等文字被压缩为接近竖排。

**解决方案**

1. 右侧详情面板的主动作区固定在底部，内容区域独立滚动。
2. 把状态、阻塞原因和主动作放在首屏；次要参数折叠到“更多参数”。
3. 1280×720 下缩短标题区和 PU 页签高度，避免多层固定区域占用曲线空间。
4. PU 页签保持单行文字，宽度不足时允许横向滚动，不进行单字换行。
5. 对可滚动面板显示稳定的滚动条或渐隐提示。

**验收标准**

- 1280×720 下，“应用/取消”“报警确认/复位”等主动作无需滚动即可看到。
- PU2–PU10 页签可以横向滚动，但状态文字不拆成竖排。
- 所有内部滚动区域都有明确的视觉提示。

### 9. 设置入口无响应

**问题表现**

左侧“设置”按钮可以点击，但页面没有跳转、弹层、Toast 或禁用状态。

**解决方案**

- 如果设置功能尚未开发，暂时隐藏入口；或
- 显示禁用状态和“暂未开放”；或
- 提供最小设置页，包括权限、语言、时间、显示和诊断信息。

**验收标准**

- 所有可点击入口都必须产生可观察结果。
- 未实现功能不得表现为正常可用按钮。

### 10. 报警列表缺少来源定位

**问题表现**

报警列表目前主要提供确认和复位，但不能直接打开报警所属单元或检测曲线。操作员需要关闭抽屉、查找 PU、打开详情，再进入曲线页。

**解决方案**

为每条报警增加与类型匹配的定位动作：

- 单元报警：`定位 PU7`；
- 信号报警：`查看 PU7 曲线`；
- 整机报警：`查看整机状态`；
- 点击报警主体默认执行定位，确认和复位仍使用独立按钮。

定位后应保留报警上下文，例如在详情页顶部显示：`来自报警：PU7 凹版辊驱动停机`。

**验收标准**

- 从报警抽屉到对应对象详情不超过一次点击。
- 定位后对象被选中并高亮，报警原因仍可见。

### 11. 弹层和抽屉缺少完整交互闭环

**问题表现**

报警抽屉和原理图弹层主要依赖关闭按钮或点击背景关闭，缺少明确的对话框语义、焦点锁定和 Escape 关闭行为。

**解决方案**

1. 增加 `role="dialog"`、标题关联和模态语义。
2. 打开后把焦点移动到标题或第一个有效操作。
3. Tab 焦点限制在弹层内部。
4. Escape 关闭非危险弹层；存在未保存编辑时先提示。
5. 关闭后把焦点返回触发按钮。

### 12. 新建草稿与替换草稿文案未区分

**问题表现**

没有原检测窗的 PU 也会显示“替换草稿未保存、原检测窗仍用于偏差计算”，但实际上不存在原检测窗，偏差表也显示为空。

**解决方案**

按场景区分：

- 无原窗口：`新建草稿未保存`，说明“保存后开始用于偏差计算”；
- 有原窗口：`替换草稿未保存`，说明“当前仍使用原检测窗计算”；
- 已保存：`当前检测窗已应用`；
- 信号异常：`信号中断，保留最后有效帧，暂停偏差更新`。

## 四、建议的目标流程

### 1. 整机到单元详情

`整机浏览 → 选择 PU → 查看只读详情 → 查看曲线或处理报警`

原则：选择和查看不得创建草稿、修改参数或改变设备控制状态。

### 2. 报警处理

`报警发生 → 报警锁存 → 操作员确认 → 故障条件恢复 → 执行复位 → 满足启动条件 → 二次确认启动 → 报警归档`

原则：报警未完成确认和复位前，不得显示为完全正常；确认报警不等于故障恢复。

### 3. 检测窗编辑

`打开曲线 → 查看正式检测窗 → 点击编辑/新建 → 生成草稿 → 调整预览 → 应用或取消 → 记录变更`

原则：所有调整方式使用同一种草稿机制，禁止部分操作立即提交、部分操作等待确认。

### 4. 页面切换

`进入页面 → URL 与当前 PU 同步 → 内部切换同步更新 URL → 离开前处理未应用修改 → 返回整线摘要`

原则：页面显示、应用状态和 URL 必须保持一致；返回整机时按当前版本规则清除 PU 上下文。

## 五、页面展示优化建议

### 1920×1080

建议继续作为主要设计基准，保留以下优势：

- 顶部整机状态、线速度和报警摘要；
- 中部工艺路径与印刷单元状态带；
- 右侧上下文面板；
- 底部速度、张力和最新事件信息；
- 颜色与文字共同表达运行、警告和停机状态。

可进一步优化：

- 提升“待确认/待复位”状态的视觉优先级；
- 降低装饰性英文标题的权重，让中文任务名称更突出；
- 报警状态优先于普通生产指标；
- 对真正可操作的区域增加更明确的交互反馈。

### 1280×720

建议使用专门的紧凑布局，而不是简单压缩 1920 布局：

- 顶部只保留工单、速度、整线状态和报警；
- 时间、幅宽等次要信息可合并到状态详情；
- 右侧面板主动作吸底；
- 参数区优先显示四项关键数据，其余折叠；
- PU 状态带和 PU 页签允许横向滚动；
- 报警抽屉必须拥有独立滚动区域。

## 八、当前版本值得保留的设计

1. 1920×1080 下整机视图结构清晰，工艺路径和单元状态能够快速建立设备全局认知。
2. 状态同时使用颜色、文字和图形表达，没有完全依赖颜色。
3. 从检测曲线返回整机时按最终规则清除 PU 详情上下文，恢复整线摘要，避免残留选择影响下一次操作。
4. 报警已经具备“确认、恢复、复位、启动”的基础状态模型。
5. 启动、删除检测窗和重新创建检测窗等高风险操作已有二次确认意识。
6. 数据新鲜度、曲线冻结、信号中断、最后接收时间等信息符合工业产品需求。

这些设计可以继续保留，后续重点应从“信息是否展示出来”转向“状态是否可信、操作是否可撤销、流程是否能安全闭环”。

## 九、第二轮演示案例复核（合并内容）

本节合并第二轮演示案例复核的内容，重点关注客户演示时的完整性、视觉可信度、流程可讲解性和现场稳定性。它是第一轮产品意见的补充，不替代《产品计划》的最终范围。

### 9.1 复核口径与总体结论

后续确认口径如下：

- 不增加可见的“演示场景控制”面板，也不增加固定场景 URL；
- 演示数据每次刷新从相同初始状态开始；
- 关键状态按约 90 秒间隔自动推进，避免讲解过程中频繁跳变；
- 报警统计中的“待复位”只表示故障已恢复、报警已确认且当前确实可以执行复位的停机报警；
- 活动故障仍显示“故障仍存在”，不计入可执行的“待复位”；
- 以上口径与《产品计划》冲突时，以《产品计划》和当前实现为准。

按演示案例标准，当前版本已经达到可展示水平。主线可以概括为：

```text
整机状态总览
  → 发现报警单元
  → 打开报警处理
  → 定位对应 PU
  → 查看单元详情
  → 进入锁定标记曲线
  → 新建或编辑检测窗
  → 处理信号异常或报警
  → 返回整线摘要
```

当前不应因缺少 PLC 指令回执、服务端持久化、多终端同步、权限和永久审计而否定演示版成果；这些属于生产化建设阶段。

### 9.3 已适合对外演示的部分

#### 整机首页

- 工单、材料、速度、整线状态和报警摘要分区明确；
- 2.5D 工艺路径可以快速传达设备结构；
- PU 状态带适合展示运行、待确认、待复位等任务状态；
- 右侧详情和底部速度、张力、事件区构成完整信息层级；
- 1920×1080 下无需页面级滚动即可完成主流程。

#### 报警处理

- 顶部能够表达停机级报警、待确认和待复位等状态；
- 报警抽屉支持需处理、活动、待确认和待复位筛选；
- 多报警列表可以独立滚动；
- 报警可以定位到整机、单元或对应曲线；
- 定位后显示报警来源上下文；
- 抽屉具备关闭、Escape、焦点控制和焦点返回。

#### 检测窗编辑

- 普通查看 PU 不自动生成草稿；
- 只有点击“新建检测窗”或“编辑检测窗”才进入草稿流程；
- 新建草稿和替换草稿文案区分；
- 调整过程只修改草稿，不直接覆盖正式检测窗；
- “应用检测窗”和“取消修改”均可见；

- 离开存在未应用修改的页面时会触发保护；

#### 页面跳转

- 整机选择 PU 后 URL 带上当前 PU；
- 进入检测页时自动选择对应 PU；

- 设置入口有明确的暂未开放反馈。

### 9.4 演示稳定性与状态一致性重点

#### 自动场景变化

早期复核曾建议增加“正常运行、PU7 停机报警、信号中断”等可见场景控制。但当前最终方案不增加该面板，也不提供固定场景 URL，原因是避免把演示控制混入正式 HMI 交互。

当前采用：

- 固定随机种子；
- 每次刷新从相同初始状态开始；
- 关键阶段约 90 秒才推进；
- 演示前通过刷新页面回到初始状态；
- 信号中断仍可使用页面中明确的“模拟信号中断（演示）”按钮主动触发。

演示者的现场准备重点是提前刷新并按时间线讲解，而不是依赖场景面板切换。

#### PU 报警未闭环时的整机启动

整机启动条件必须汇总当前停机级报警：

```text
存在活动停机报警
或存在已恢复但待复位停机报警
→ 整机启动按钮禁用
→ 展示最关键阻塞原因
```

推荐文案：

```text
整机暂不可启动
PU7 停机报警尚未复位
```

完成“确认报警 → 条件恢复 → 复位报警”后，整机启动按钮才变为可用；启动仍需要二次确认。

#### 主 Canvas、状态带和详情一致

同一个 PU 的主状态应统一来自 `stationAttentionLevel`、`stationStatusText` 和 `stationNeedsAction` 等派生规则，至少区分：

- 运行：绿色；
- 正常停止：灰色；
- 待确认：黄色；
- 活动警告：黄色；
- 停机报警：红色；
- 待复位：红色锁存；
- 信号中断：黄色或紫色。

Canvas 空间不足时允许使用“确认、报警、复位、信号”等短文案，但不能把待复位停机级报警降级为普通灰色停止。

#### 深链 PU10 可见性

当打开 `/lock-mark?pu=PU10`、报警定位到 PU9/PU10，或页面内部切换到当前 PU 时，应自动将对应页签滚动到可视区：

```js
selectedElement.scrollIntoView({
  block: 'nearest',
  inline: 'center'
})
```

整机状态带和锁定标记页签都应遵循同一规则，避免标题显示 PU10 但可视区域仍停留在 PU2–PU9。

### 9.5 不阻塞演示的增强项

以下内容属于演示加分项，不应阻塞当前交付：

1. 目标速度变化超过 `10 m/min` 时显示轻量确认，并明确“模拟目标速度”；
2. 版辊微调保持固定 `0.01 mm` 步长，限制在 `-0.50 ～ +0.50 mm`，每次操作显示 Toast，并提供恢复零位；
3. 检测窗应用后使用 `sessionStorage` 保存，或明确提示“演示会话内已应用，刷新后重置”；
4. 1280×720 优先保留工单号、实际速度、整线状态和报警摘要，材料幅宽可移入详情；
5. 报警统计使用“3 条活动报警，其中 2 条待确认 · 1 条需复位”这类文案，说明统计可能存在重叠；
6. 报警上下文条提供关闭按钮，定位讲解完成后释放页面空间；
7. 顶部使用低干扰的“模拟数据”说明，避免客户误以为已经连接真实 PLC。

### 9.6 推荐客户演示脚本

建议完整演示控制在 5–7 分钟：

#### 第一段：整机总览（约 1 分钟）

3. 介绍中间 2.5D 工艺路径；

5. 说明同一页面可适配 1280×720 工业触控屏。

3. 定位 PU7；
4. 展示 PU7 详情和报警原因；
5. 确认报警；
6. 等待条件恢复；
7. 执行复位；
8. 展示启动条件解除，再进行二次确认启动。

#### 第三段：锁定标记与检测窗（约 2 分钟）

2. 介绍 1200 点信号、首色/前色/本色参考线；
3. 点击“新建检测窗”；

5. 展示“草稿未应用”；
6. 点击“应用检测窗”；

2. 展示最后有效帧保留；
3. 打开报警处理；
4. 点击“查看 PU 曲线”；

1. 切换到 1280×720；
2. 展示右侧主操作吸底；
3. 展示报警列表独立滚动；
4. 展示 PU 页签横向滚动；
5. 打开 PU10，确认选中项自动进入可视区。
