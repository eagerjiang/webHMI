# VISU·19 Web HMI UI 设计优化意见

> 评审角色：工业界 UI / HMI 设计评审
>
> 评审对象：当前运行中的 `/overview`「整机浏览」与 `/lock-mark`「锁定标记」页面
>
> 评审日期：2026-08-14
>
> 目标设备：1920×1080 横向工业触摸屏；同时检查 1280×720 的降级表现

## 1. 先说结论

当前界面已经具备比较清晰的工业 HMI 基础：深色低反光底色、青色操作色、绿色运行态、黄色警告、红色停机级报警；整机页采用“顶部全局状态 + 中央整线工艺图 + 右侧上下文 + 底部速度/卷材/事件”的结构，锁定标记页也形成了“曲线 + 检测窗信息 + 工具栏”的工作台形态。

下一步不建议继续堆叠字段，而应优先解决以下四件事：

1. 让操作员在 3 秒内看懂“整线是否运行、速度是多少、是否有活动报警、报警来自哪个 PU”。
2. 让 PU 的“工艺颜色”和“设备状态”彻底分离，避免黄色既代表颜色又被误读为警告。
3. 保证锁定标记页面在不同分辨率下，色组切换、曲线、检测窗操作和应用/取消动作都不会被挤压或截断。
4. 将高风险动作固定在可见、可确认、可追溯的位置，减少误触和误判。

## 2. 当前界面做得好的地方

### 2.1 信息架构方向正确

- 顶栏常驻工单、材料幅宽、实际线速度、整线状态和报警摘要，符合生产现场“先看全局、再定位局部”的阅读顺序。
- 整机页保留放卷 → PU1–PU10 → 收卷的横向工艺路径，符合凹版印刷机的真实走料认知。
- 单击色组后，右侧进入当前 PU 上下文；“查看 PU 检测曲线”作为明确入口，符合从设备定位到信号诊断的工作流。
- 锁定标记页将曲线、检测窗坐标、MD/CD 偏差、阈值和微调工具放在同一工作区，任务闭环是完整的。

### 2.2 状态语义已经有较好的基础

- 整线“运行/停止”和 PU“运行/停止/警告/停机”能够独立表达，避免普通 PU 报警直接覆盖整线状态。
- 报警摘要使用红/黄分级，且展示“活动、待确认、待复位”数量，已经具备操作闭环意识。
- 检测窗采用草稿 → 应用/取消的事务式流程，优于直接覆盖生产参数。
- 锁定标记信号具备“实时、冻结、信号中断、恢复中”等状态文案，不应再用普通灰色停止代替信号异常。

### 2.3 触控与可访问性意识较好

- 关键按钮大多达到 48px 左右的触控高度。
- 已提供 `focus-visible` 轮廓、Esc 取消、Enter 确认、Delete 删除确认等键盘反馈。
- 报警抽屉、详情面板和曲线工作台已经有独立滚动区域的设计方向。

## 3. 当前画面中最需要优化的问题

### P0：必须先修复的可用性问题

#### 3.1 锁定标记色组条必须始终保持“单行可扫描”

锁定标记页在 `LockMarkPage.vue` 中将 PU 按钮放入 `.pu-tab-scroll`。这个容器必须是横向 flex，并允许只在色组条内部横向滚动；不能让 PU2–PU10 垂直堆叠。垂直堆叠会把色组条撑高，导致曲线和右侧检测面板被推到首屏以下。

建议：

- `.pu-tab-scroll` 使用 `display:flex; flex:1 1 auto; min-width:0; overflow-x:auto`。
- `.pu-tab` 设置 `flex:0 0 auto; white-space:nowrap`，禁止按钮内容换行。
- 当发生横向溢出时，在右侧保留渐隐遮罩或滚动提示，不要让操作员猜测还有 PU 未显示。
- 1920×1080 下应尽量一次显示 PU2–PU10；1280×720 下允许内部横向滚动，但当前选中 PU 必须自动滚入可见区域。

对应位置：[`LockMarkPage.vue:175`](/Users/jiangqianwen/projects/webHMI/src/components/LockMarkPage.vue:175)、[`styles.css:412`](/Users/jiangqianwen/projects/webHMI/src/styles.css:412)。

#### 3.2 右侧详情和检测面板要“内容滚动、动作固定”

右侧详情包含原理图、状态、报警、参数和检测曲线入口；锁定标记页还包含检测窗、偏差表和删除/冻结动作。如果整块面板一起滚动，关键动作容易离开视线，也容易在低高度屏幕上出现“看到了数据却找不到应用按钮”的问题。

建议：

- 内容区单独滚动，底部固定“查看曲线 / 应用检测窗 / 取消修改 / 冻结曲线”等动作区。
- 固定动作区上方使用 1px 分隔线和轻微阴影，明确它与数据区的边界。
- 有滚动内容时显示细滚动条或“向下还有内容”的渐隐提示；不要只依赖浏览器默认滚动行为。
- 删除、重新创建等破坏性动作保持次要层级，并在动作附近显示影响对象和当前状态。

对应位置：[`OverviewPage.vue:143`](/Users/jiangqianwen/projects/webHMI/src/components/OverviewPage.vue:143)、[`LockMarkPage.vue:190`](/Users/jiangqianwen/projects/webHMI/src/components/LockMarkPage.vue:190)。

#### 3.3 报警摘要需要从“数量提示”升级为“来源 + 影响 + 下一步”

顶栏的“停机报警待复位 1 活动 · 4 待确认 · 1 待复位”信息密度较高，但第一眼不容易判断：报警来自哪个 PU、是否影响整线、现在应该确认还是复位。

建议：

- 顶栏保留严重级别和数量，具体来源放入报警抽屉首屏摘要。
- 抽屉顶部增加三项固定摘要：活动报警、待确认、待复位；每项数字大于标签。
- 每条报警采用固定顺序：`来源 PU → 严重级别 → 影响范围 → 原因 → 操作`。
- “确认报警”和“复位”不能只靠颜色区分：使用不同文案、图标和状态反馈。
- 已恢复报警与活动报警分组显示；已恢复项目降低视觉权重，但保留时间和确认状态。

#### 3.4 运行状态、报警状态、工艺颜色继续保持三套独立编码

PU 的黄色、橙色、紫色等工艺色只代表油墨/印刷色，不能直接承担警告含义。状态必须依靠状态点、文字、边框或形状表达。

推荐规则：

| 语义 | 主表达 | 辅助表达 |
| --- | --- | --- |
| 工艺颜色 | 版辊底部色带 / 色点 | 色组名称 |
| 运行 | 绿色状态点 +“运行” | 材料运动线 |
| 停止 | 灰色状态点 +“停止” | 不使用红色 |
| 警告 | 琥珀色状态点 +“警告” | 警告图标 |
| 停机级报警 | 红色菱形/状态点 +“停机” | 影响范围 |
| 当前选中 | 青蓝描边 + 右侧同步 | 不改变工艺色 |
| 数据延迟 | 独立数据状态标签 | 不等同设备报警 |

### P1：建议在本轮设计迭代完成

#### 3.5 整机 Canvas 的标签需要更适合现场远视

当前整线图的比例关系清晰，但在 1280×720 截图中，PU 标签、走料方向和设备名称偏小，操作员需要靠近屏幕才能确认具体色组。

建议：

- 设备编号使用固定两位数 `01–10`，状态放在编号下方，减少长句塞入图形内部。
- Canvas 内只保留“编号、运行/警告/停机、工艺色”；详细参数放到右侧面板。
- 当前选中 PU 增加青蓝外框和一条指向右侧面板的连接关系。
- 鼠标/触摸移入时显示简短 tooltip，但不要依赖 tooltip 传达关键安全状态。
- 走料线、同步线和报警锚点使用不同线型，避免全部采用同一种青色。

#### 3.6 总览右侧空状态需要变成“可行动摘要”

未选择 PU 时，右侧目前主要展示整机速度、需处理报警和数据状态，结构是对的，但空间利用率偏低。建议加入一块轻量“当前作业摘要”，不新增业务字段，只重新组织已有信息：

```text
整线运行中
实际线速度 24.0 m/min
需处理报警 2 条
最新来源 PU7 · 凹版辊驱动停机
[打开报警列表]
```

这能让首屏在不选择任何 PU 时仍然具有明确的下一步，不会出现大片空白。

#### 3.7 底部信息轨需要建立优先级

当前底部同时放入实际/目标速度、目标速度调节、快捷速度、加减速时间、放卷/收卷、张力和最新事件。1920 宽度下可接受，但 1280 宽度下容易变成小字号和多行文字混排。

建议按以下优先级处理：

1. 常驻：实际线速度、目标线速度、整线状态、活动报警/最新事件。
2. 次常驻：放卷/收卷当前轴、卷径/剩余长度、张力。
3. 可展开：加减速时间、快捷速度预设、次要工艺摘要。

在 1280×720 下将底部轨拆成“速度 + 报警”主行和“卷材/张力”折叠行，不能通过隐藏报警来换空间。

#### 3.8 锁定标记曲线要强化“可测量性”

曲线本身已经能表达首色、前色、本色和波形，但现场调试更关心“检测窗在哪里、当前值是否超过阈值、操作后会改变什么”。

建议：

- 检测窗使用半透明填充 + 左右边界手柄，草稿窗使用琥珀色，已应用窗使用青蓝色。
- 在曲线内显式标出 `0.10 mm 预警`、`0.20 mm 停机` 对应的状态说明；阈值表与图中语义保持一致。
- 增加当前游标读数和“最新帧/最后显示帧”的层级区分，避免实时刷新时用户误把旧帧当新值。
- `冻结曲线` 后固定显示“冻结时间、数据时间戳、恢复实时”三项信息。
- 信号中断时保留最后一帧，但在画布中央覆盖“信号中断，禁止将旧帧作为实时值”的明确提示。

#### 3.9 动作文案要直接说明结果

建议统一以下文案：

| 当前文案 | 建议文案 | 原因 |
| --- | --- | --- |
| 重新创建 | 新建替换检测窗 | 明确不会立即覆盖原窗 |
| 应用检测窗 | 应用检测窗并开始计算 | 明确应用后的业务影响 |
| 删除检测窗 | 删除当前检测窗 | 明确作用对象 |
| 恢复视图 | 重置曲线视图 | 比“恢复”更容易理解 |
| 版辊 −0.01 mm | 版辊偏移 −0.01 mm | 说明修改的是偏移量 |
| 模拟信号中断 | 模拟信号中断（演示） | 避免现场误以为真实断线 |

#### 3.10 “更多参数”需要显示展开后的范围

当前折叠参数包括刮刀压力、压印辊合压压力、干燥温度和油墨黏度，符合首屏优先原则。但展开后应在标题旁显示“4 项”，并明确这些是监视值而非可直接控制项，避免操作员误以为点击数字即可改变设备参数。

### P2：作为设计系统和后续迭代储备

- 建立统一的状态组件：`StatusDot`、`StatusBadge`、`AlarmBadge`、`DataFreshness`，避免不同页面自行拼接颜色和文案。
- 建立 8/16/24px 间距 token，减少当前 CSS 后段重复覆盖导致的样式漂移。
- 将中英文辅助文案分成“标题英文”和“现场标签中文”两套层级，避免每个区块都同时显示大写英文造成噪声。
- 为报警、选中、草稿、冻结、数据延迟状态补充颜色之外的图标或形状，降低色觉差异带来的误判。
- 关键状态变化使用短暂的边框/状态点动画，不让整张卡片闪烁；报警声音或更强提示应由设备策略决定，UI 不自行推断。

## 4. 推荐的视觉基线

### 4.1 尺寸和布局

| 项目 | 1920×1080 基线 | 1280×720 降级 |
| --- | ---: | ---: |
| 顶部状态栏 | 80px | 80px |
| 左侧导航 | 96px | 64px 横向导航或抽屉 |
| 页面左右内边距 | 24px | 14–16px |
| 面板间距 | 16–20px | 10–16px |
| 普通触控目标 | ≥48×48px | ≥48×48px |
| 关键动作目标 | 52–56px 高 | 52–56px 高 |
| 生产关键数字 | 28–40px | 24–32px |
| 普通正文 | 16–18px | ≥16px |
| 状态辅助文字 | ≥12px | ≥11px |

### 4.2 颜色使用

当前颜色方向可继续沿用，但要控制颜色面积：

- 背景和面板使用低饱和蓝黑色，避免大面积纯黑造成边界消失。
- 青蓝色只用于当前选中、主要操作、可交互焦点和数据链接。
- 绿色只用于正常/运行，不用于“数据正常”以外的所有成功提示。
- 黄色用于警告和待确认，不用于普通工艺色。
- 红色用于停机级报警、删除确认和严重偏差；不要把已恢复报警渲染成同样强度的红色。

### 4.3 字体和数字

- 关键数字使用等宽数字或统一数字宽度，避免速度和偏差刷新时产生横向跳动。
- 单位与数值保持同一信息组，但单位颜色降低一级，数值保持高对比。
- 英文 eyebrow 用于导航和分区即可，不应与中文正文争夺视觉焦点。
- 现场标签优先写清对象和位置，例如“放卷张力”“段间张力”“收卷张力”，不要只写“张力”。

## 5. 页面级改造建议

### 5.1 `/overview` 整机浏览

推荐首屏结构：

```text
顶部：工单 / 材料幅宽 / 实际线速度 / 整线状态 / 报警摘要 / 时间
左侧：整机浏览 / 锁定标记 / 报警辅助 / 设置
主区：放卷 → PU1–PU10 → 收卷的整线图
右侧：整机摘要或当前 PU 详情
底部：速度主读数 / 卷材与张力 / 最新事件
```

交互重点：

- 首次进入不伪造默认 PU；无选择时展示整机摘要。
- 单击 PU 先建立上下文，再由“查看详情”和“查看检测曲线”进入下一层。
- 报警状态带提供“全部 / 需处理”筛选，但筛选结果必须保留“当前无结果”的明确空状态。
- 点击报警来源时，右侧详情应同步定位到对应 PU，并保留报警上下文提示。

### 5.2 `/lock-mark` 锁定标记

推荐首屏结构：

```text
标题与来源：当前来自哪个 PU / 是否来自报警
色组条：PU2–PU10，单行横向滚动
左侧：1200 点信号曲线、检测窗和参考线
右侧：检测窗坐标、MD/CD 偏差、阈值、应用/取消动作
底部：检测窗微调、曲线视图、版辊偏移
```

交互重点：

- 画框后先显示草稿，不改变当前偏差计算；点击“应用检测窗并开始计算”后再切换为正式窗。
- 取消修改恢复到原检测窗，不清空旧数据。
- 信号中断时冻结最后一帧并禁止用户将其误认为实时数据。
- 删除操作必须二次确认，确认文案包含 PU 编号和“当前检测窗”。

## 6. 验收清单

### 6.1 视觉与布局

- [ ] 1920×1080 下无页面级横向/纵向滚动，无内容被底部裁切。
- [ ] 1280×720 下曲线、报警和当前动作仍可见；允许内部滚动，但有明显滚动提示。
- [ ] 锁定标记色组条保持单行；PU2–PU10 的选中、已设窗、草稿状态一眼可区分。
- [ ] Canvas 内工艺颜色不承担状态含义，状态点/文字/边框保持统一。
- [ ] 右侧面板滚动时，关键动作区固定可见。

### 6.2 操作与安全

- [ ] 操作员 3 秒内可回答整线状态、实际速度、最高报警和报警来源。
- [ ] 所有关键按钮触控区域不小于 48×48px，危险动作有二次确认。
- [ ] 检测窗草稿、应用、取消、删除四个状态可以通过颜色、文字和位置区分。
- [ ] 信号中断、冻结、恢复实时均显示时间戳和明确状态。
- [ ] 键盘焦点可见，Esc/Enter/Delete 行为与界面文案一致。

### 6.3 信息可信度

- [ ] 实际线速度与目标线速度标签完整，单位不脱离数值。
- [ ] 张力、压力、速度带有测量对象或位置，不出现裸字段。
- [ ] 活动、待确认、待复位、已恢复报警分组和数量相互一致。
- [ ] 数据延迟只表达通信/快照状态，不直接替代设备健康状态。
- [ ] 所有“暂无数据”使用 `—` 或明确空状态，不用模拟数字填充。

## 7. 建议实施顺序

1. 修复 PU 色组条的横向布局、内部滚动和当前项自动定位。
2. 固化右侧详情/检测面板的内容滚动与动作区固定规则。
3. 重排报警摘要和报警抽屉的来源、影响、操作层级。
4. 调整 1280×720 底部信息轨，保留报警和速度，折叠次要参数。
5. 优化 Canvas 标签、曲线检测窗、阈值和信号中断提示。
6. 最后再统一 token、组件、图标和动画，避免在布局未稳定前做表面美化。
