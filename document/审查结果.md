当前实现是一个“可运行、视觉完成度较高的演示版”，但按照产品计划的严格 P0/P1 验收口径，尚未达到可直接提交的标准。

> P0 核心功能部分通过，P0 提交门槛未完全通过；P1 已实现部分展示能力，但关键交互闭环仍不完整。当前版本适合作为面试交流用的演示雏形，不建议直接作为最终考核交付版本。

## 4. P0 未通过项

### 4.1 1920×1080 下存在页面纵向滚动

产品计划要求 1920×1080 下无需滚动、无内容截断。实际检查结果：

```text
viewport: 1920 × 1080
document height: 1160
```

整机浏览页和锁定标记页均存在纵向溢出，因此 P0 的“无滚动、无内容截断”没有通过。

相关实现主要位于：

- `src/App.vue` 的工作区高度和内边距；
- `src/styles.css` 的 Canvas、底部工具条和页面间距。

建议压缩工作区高度、Canvas 高度或底部工具条高度，将页面约束在顶部状态栏 80px + 内容区 1000px 内。

### 4.2 整机色组必须双击才能进入锁定标记

产品计划要求点击 PU2–PU10 的完整命中区域后直接进入对应锁定标记页面。

当前实现：

```js
emit('select', id)
if (id !== 'PU1' && e.type === 'dblclick') emit('enter-lock', id)
```

结果：

- 单击：只选中色组并展开详情；
- 双击：才进入锁定标记。

这与“点击 PU3 → 自动进入 PU3 锁定标记”的产品流程不一致，也不符合工业触控场景下一次操作完成的要求。

相关文件：`src/components/MachineCanvas.vue`。

### 4.3 整机状态没有真正按 1 秒变化

`tickMachine()` 每秒只更新：

- 当前时间；
- 速度平滑值；
- 总计长度；
- 放卷/收卷摆臂位置。

它没有更新：

- `machine.runState`；
- 各色组 `runState`；
- 各色组 `alarmState`；
- 报警集合；
- 运行/停止动画状态。

PU7 停止、PU4 警告、PU8 警告目前主要是初始化静态数据。当前版本能证明“状态展示”，但不能证明“状态数据每 1 秒刷新并驱动颜色、图标和动画变化”。

相关文件：

- `src/stores/hmi.js`
- `src/data/mock.js`

### 4.4 顶部运行状态点没有完全跟随数据

顶部运行状态文字使用 `machine.runState`，但状态点固定写成：

```html
<span class="status-dot run"></span>
```

如果后续 `machine.runState` 变为 `stop`，文字会变成“停止”，圆点仍显示绿色运行状态，存在状态语义冲突。

相关文件：`src/components/TopBar.vue`。

### 4.5 运行和停止动画不完整

产品计划要求走料、辊筒旋转与运行/停止状态联动。当前整机 Canvas 使用静态走料路径和静态辊筒图形，没有看到基于 `requestAnimationFrame` 或运动相位的实际动画控制。

### 5.1 已实现的 P1 能力

- PU2–PU10 色组切换；
- 首色、前色、本色参考竖线；
- 底部印刷颜色条带；
- 检测窗数据坐标展示；
- 检测窗删除；
- 检测窗左右微调；
- 曲线缩放、平移；
- 版辊横向微调；
- 本色、前色、首色偏差表；
- 手动冻结按钮入口；
- warning/stop 报警分级；
- 整机报警和 PU 报警来源区分；
- 报警人工确认。

### 5.2 尚未完成或存在缺陷的 P1 能力

#### 5.2.1 检测窗不能拖动和缩放

Canvas 绘制了可见手柄，但指针事件无论点击哪里，都被处理为重新创建检测窗。因此尚不支持：

- 拖动已保存检测窗主体；
- 八方向调整大小；
- 选中窗口后再编辑；
- 编辑过程取消；
- 编辑前快照恢复。

相关文件：`src/components/SignalCanvas.vue`。

#### 5.2.2 删除检测窗没有二次确认

删除是破坏性操作，但当前点击后直接清空窗口：

```js
state.windows[state.selectedStationId] = null
```

这不符合工业触控安全约束和产品计划中的“确认后立即删除”要求。

相关文件：

- `src/components/LockMarkPage.vue`
- `src/stores/hmi.js`

#### 5.2.3 重新创建会直接覆盖旧窗口

当前“重新创建检测窗”直接调用保存逻辑，没有替换提示、草稿状态、确认保存、取消编辑或恢复上一次有效位置。

#### 5.2.4 冻结曲线没有真正冻结显示帧

`toggleFreeze()` 只改变 `freezeMode` 和显示时间，但 `currentFrame` 仍然直接返回最新的 `state.frames[selectedStationId]`。后台 `tickSignals()` 仍持续替换 `state.frames`，所以点击“冻结曲线”后曲线仍会继续更新。当前只冻结了时间标记，没有冻结曲线内容。

相关文件：`src/stores/hmi.js`。

#### 5.2.5 偏差没有真正由检测窗和曲线计算

偏差表中的纵向偏差主要来自初始化模拟值：

```js
long: selected?.offsetLongitudinalMm ?? 0.03
```

移动检测窗不会联动改变纵向偏差。版辊微调能够影响横向偏差显示，但整体还不是完整的数据驱动偏差计算闭环。

#### 5.2.6 曲线平移/缩放后存在绘制起点风险

曲线过滤掉视口外点后，仍使用原数组索引判断是否调用 `lineTo()`。当视口起点大于 0 时，第一个可见点可能直接使用 `lineTo()`，导致曲线起点连接异常。

#### 5.2.7 工艺视图/结构视图按钮没有真正切换

两个按钮目前是静态入口：

- “工艺视图”固定为 active；
- “结构视图”没有状态切换；
- Canvas 绘制内容不会随按钮变化。

这与产品计划要求的“结构视图 / 工艺视图切换”不一致。

## 6. 触控与视觉验收问题

产品计划要求普通按钮不小于 48×48px，关键操作建议 56px 高。实际检查发现：

- 普通按钮高度约 44px；
- PU 色组按钮高度约 42px；
- 速度步进按钮高度约 38px；
- 底部窗口、视口和版辊工具按钮多数为 44px。

鼠标操作基本可用，但对工业触摸屏来说命中区域偏小，尤其是：

- PU 色组切换；
- 窗口左右微调；
- 速度加减；
- 版辊横向微调；
- 删除检测窗。

另外，部分辅助文字字号偏小，不完全符合产品计划中“正文不小于 18px”的严格要求。当前视觉更接近桌面端演示屏，而非完全按工业触摸屏验收标准收敛。

## 7. 数据架构评价

当前定时器直接放在 `useHmi()` Store 中：

```js
machineTimer = setInterval(tickMachine, 1000)
signalTimer = setInterval(tickSignals, 500)
```

这种方式适合小型演示，但与产品计划建议的职责边界仍有差距。当前结构更接近：

```text
Store 内部定时器 + Store 状态 + View
```

计划中的结构是：

```text
MockMachineSource
  → machine store
  → 顶部状态栏 / 2.5D Canvas / 参数与报警

MockSignalSource
  → signal frame buffer
  → 曲线渲染层 / 信号异常报警

用户交互
  → mark window store
  → 检测窗 / 偏差表 / 色组状态
```

当前实现的优点是简单、可运行；不足是：

- 数据源和页面状态耦合；
- 难以单独测试机器刷新和信号刷新；
- 后续接入 WebSocket、PLC 或真实数据源时替换成本较高；
- 信号异常、报警恢复和演示脚本继续扩展时 Store 会快速膨胀。

这不是当前 P0 的立即淘汰项，但会成为面试代码走查和工程能力交流时的重点追问项。

## 9. 建议修复优先级

### 必须先修复的 P0 问题

1. 修复 1920×1080 页面纵向滚动，确保两页 `scrollHeight <= 1080`。
2. 将 PU2–PU10 的整机色组单击行为改为直接进入对应锁定标记页。
3. 增加真正的 1 秒状态刷新场景，至少让运行/停止、警告和报警状态发生可演示变化。
4. 让顶部状态点、Canvas 状态点、文字和走料动画跟随实际状态数据。
5. 确保最终 20 秒录屏按产品计划顺序完整演示四个片段。

### P1 加分修复

1. 将检测窗编辑拆分为主体拖动、八方向缩放和空白区域新建。
2. 删除检测窗增加二次确认。
3. 重新创建检测窗增加替换保护、草稿、确认和取消。
4. 使用独立的 `displayedFrame` 和 `latestReceivedFrame` 实现真正冻结。
5. 根据当前检测窗、波峰和参考线计算纵向偏差。
6. 修复曲线平移/缩放后的第一个可见点绘制逻辑。
7. 实现工艺视图/结构视图真正切换。
8. 将关键触控按钮统一提升到至少 48px，重要操作提升到 56px。

### 11.4 复审发现的剩余风险

#### 11.4.1 整机每秒脚本需要覆盖完整状态集合

复审过程中发现，车速、长度、摆臂以及部分 PU 警告能够按秒变化，但演示脚本还需要明确覆盖整机运行/停止、PU2–PU10 状态和报警集合的切换。最终验收不能只证明“画面在刷新”，还要能观察到状态数据驱动文字、颜色、状态点和动画变化。

验收建议：使用固定种子和相对页面加载时间的可复现时间线，至少覆盖运行中、PU 警告、PU 停止和恢复等阶段；不增加可见演示控制面板，也不依赖固定场景 URL。

#### 11.4.2 性能和稳定性证据仍需补充

当前已完成构建、基础运行态和虚拟场景回归，但尚未形成以下证据：

- 真实浏览器连续运行 5 分钟记录；
- 内存是否持续增长的检查；
- Canvas FPS 或帧耗时采样；
- 500ms 曲线刷新期间拖动检测窗的性能记录；
- 完整自动化端到端测试。

这属于交付前的验证证据补充，不应被描述为已经完成的性能指标，也不改变已通过的基础构建结论。

#### 11.4.3 触控尺寸和字号仍需按工业屏复核

通用按钮已按 48×48px 方向收敛，但色组状态带、筛选按钮和部分辅助文字仍可能偏小。需要在 1920×1080 设备或等比例触摸模拟环境中复核：

- PU 色组切换；
- 窗口左/右微调；
- 速度加减；
- 版辊横向微调；
- 删除、确认和报警操作；
- 正文和关键状态文字的可读性。

### 11.5 P1 复审问题与实施复核结果

第二轮原始复审曾记录以下缺口：无窗口时没有默认草稿、没有取消/Escape 恢复快照、偏差未按首色主参考线计算、未显示最新接收帧、空白区拖动始终创建窗口、微调不支持长按、无有效峰提示不明确、模拟信号中断绕过超时阈值。

根据后续实施复核，这些项目已按确认方案处理：

1. PU3–PU10 无已保存检测窗时生成居中草稿，并区分草稿与正式窗口；
2. 应用、取消、离开保护、编辑快照、Escape 恢复、Enter 确认和 Delete 删除流程已纳入检测窗事务；
3. 首色由 `MockReferenceConfig.first` 提供主参考位置，前色仅作辅助比较；
4. 页面显示“最新接收”和“最后显示”时间，冻结只保持显示帧不变；
5. 无草稿时空白区用于水平平移，有草稿时才进入检测窗创建/编辑语义；
6. 窗口和版辊微调支持长按连续执行、500ms 后加速和边界限制；
7. 无有效峰、无窗口和信号异常应分别显示 `—` 或相应原因提示，避免把不同状态混为一谈；
8. 信号中断遵守 2000ms 超时，恢复需连续两帧有效数据。

以上项目属于“已纳入实现并通过基础回归”的 P1 闭环；若后续代码再次变更，应按对应验收用例重新回归，不仅凭界面截图判定通过。

### 11.6 架构与工程复核

第二轮还检查了数据边界：

- `MockMachineSource` 应生成不可变整机快照，由 Store 消费；
- `MockSignalSource` 应生成信号帧和信号质量，不直接操作页面 DOM；
- Store 负责快照、帧缓存、显示帧、检测窗、偏差、报警聚合和 action；
- 页面组件只负责渲染和派发 `selectStation`、`enterLock`、`shiftWindow`、`nudgeRoller`、`confirmAlarm` 等 action；
- 报警应保留 machine、station、signal 的影响范围，并按影响范围、级别、确认状态和时间排序；
- 页面离开或数据源停止时必须清理定时器和订阅，避免重复推送。

实施复核确认 Store action 收口、数据源分层和纯函数验收已完成基础整理；真实 WebSocket/PLC 接入、权限、审计和持久化仍不属于本次考核范围。
