# 产品优化

> 文档性质：整机浏览界面的独立优化建议  
> 适用范围：1920×1080、16:9 工业触摸屏；参数化 2.5D Canvas 整机浏览页  
> 当前状态：已确认采用“全宽总览 + 窄摘要 + 展开详情”、下版辊底部彩色半圆弧、“单击查看详情 / 显式按钮进入锁定标记”，以及“右侧详情中的简化单元原理图”。详情打开后整线 Canvas 保持可见；完整原理图通过弹层展开。

## 1. 优化目标

整机浏览页的第一目标不是展示更多设备细节，而是让操作员在进入页面后的几秒内回答以下问题：

```text
设备现在是否运行？
哪一个色组有问题？
问题属于警告、停止还是信号异常？
点击后能否快速进入下一步处理？
```

## 2. 优先级总览

### 2.1 P0：建议优先实现

| 优化项 | 建议 | 解决的问题 |
| --- | --- | --- |
| 布局模式 | 默认总览：整线 Canvas + 右侧窄摘要；点击色组或 PU 报警后进入详情，整线 Canvas 保持可见，右侧显示完整详情和简化原理图 | 解决整线内容挤在一起，同时让当前单元结构和关键数据同屏可见 |
| 顶部状态信息分层 | 固定显示车速、整机运行状态、最高报警级别、活动报警数、待确认数和时间 | 操作员快速判断整机状态 |
| 运行状态与报警状态分开 | “运行中”和“有报警”允许同时出现，不因报警直接改成“停止” | 避免误判设备状态 |
| 色组状态常驻显示 | Canvas 内显示编号、工艺色半圆弧、状态点和报警锚点；完整状态文字放在状态带和详情中 | 不需要逐个点击才能发现异常，同时避免 10 个色组文字拥挤 |
| 工艺颜色半圆弧 | 在每个色组下版辊底部绘制对应工艺颜色的半圆弧；辊筒主体保持金属灰蓝色 | 直观表达色组颜色，同时避免整只辊筒被彩色填充造成拥挤 |
| 色组完整区域可点击 | 点击整个色组主体、编号和可交互色条都能选中，命中区域不小于 48×48px | 提高工业触摸屏命中率 |
| 选中反馈同步 | Canvas 高亮、右侧详情标题、当前选中提示三处同步变化 | 让操作员确认点击已经生效 |
| 色组单击与显式跳转 | 单击色组展开右侧详情；通过详情中的“查看 PU 检测曲线”按钮进入锁定标记，不绑定双击业务动作 | 消除工业触摸屏上的时序歧义，让跨页面操作可发现、可触控、可用鼠标完成 |
| 报警空间定位 | 异常色组显示报警锚点、状态标签或摘要 | 从“有报警”快速定位到“哪里报警” |
| 走料方向和运行反馈 | 材料带使用低频箭头或短纹理表示运动；停止时动画停止 | 直观看出材料是否运行及方向 |
| 数据新鲜度 | 显示最近更新时间或数据延迟状态 | 避免把旧数据误认为实时数据 |
| 明确无数据状态 | 区分设备停止、信号中断、暂无配置、数据异常 | 避免所有异常都显示成灰色 |

首次进入整机浏览时不默认选中任何色组；右侧窄摘要显示“请选择色组查看详情”，Canvas 先承担整线总览职责。用户单击色组后才建立当前色组上下文。

布局尺寸建议：

- 总览模式下 Canvas 使用剩余可用宽度，右侧窄摘要建议约 `200–240px`，最小不低于 `180px`；这样“请选择色组查看详情”、报警摘要和当前选中提示都能保持可读。
- 详情模式下右侧展开约 `360–420px` 完整详情，顶部默认显示当前 PU 简化原理图；整线 Canvas 继续使用剩余空间，完整原理图通过弹层查看。
- 应用整体仍保持 `1920×1080`、16:9；整机 Canvas 内部采用更适合生产线的横向长条比例。
- 点击“收起详情 / 返回总览”后恢复全宽 Canvas，当前选中对象保持不变。
- 首次进入整机浏览时不默认选中色组；窄摘要显示“请选择色组查看详情”。
- 新报警出现时不自动展开右侧详情，也不改变 Canvas 尺寸；只更新顶部报警汇总、对应色组报警锚点和窄摘要。用户点击报警锚点后才展开报警详情。

### 2.2 P1：建议在 P0 稳定后实现

| 优化项 | 建议 | 解决的问题 |
| --- | --- | --- |
| 色组状态带 | Canvas 下方增加 01–10 的简洁状态带，可点击并执行同样的选中/跳转逻辑 | 复杂设备图下快速扫查十个色组 |
| 报警列表联动 | 点击某个色组报警后，右侧优先展示该色组报警，而非先打开全部报警 | 减少二次筛选 |
| 报警轻量筛选 | 仅提供“全部 / 仅报警”两种视图 | 多个异常同时出现时降低干扰，同时避免筛选概念过多 |
| 详情面板分层 | 当前对象、关键数据、更多参数分层显示 | 避免一开始堆叠过多参数 |
| 单个印刷单元原理图 | 仅在详情模式默认展示当前 PU 的结构示意，左侧展示原理图，右侧保留关键状态和操作入口；展示材料带、上下辊、版辊、油墨槽、刮刀和光电眼；不放入整机总览 | 帮助操作员快速理解当前色组的设备组成、走料关系和检测信号来源 |
| 返回状态规则 | 从锁定标记返回整机时清除当前 PU 高亮和报警上下文，恢复整线摘要；离开前先处理未应用检测窗修改 | 防止残留上下文误导下一次操作 |
| 速度信息完善 | 同时显示当前速度、目标速度、运行模式和允许范围；本版本以查看为主 | 避免只看到一个孤立速度值 |
| 速度操作反馈 | 预设速度、目标速度、手动升降速作为 P1 操作；所有操作都显示明确执行状态 | 降低误操作风险，不让总览页变成控制面板 |

### 2.3 P2：后续工业化扩展

- 更复杂的报警聚合、影响范围和报警历史查询。
- 设备结构视图与工艺视图的更多联动。
- 角色权限、操作审计和操作员确认记录。
- 与真实 PLC、WebSocket 或设备报警系统的接入。
- 更复杂的设备定位、导航和维护流程。

## 3. 2.5D Canvas 交互优化

### 3.1 色组命中区域

建议把单个色组的完整设备区域作为一个统一命中对象，而不是只让底部编号文字可点击：

- 色组主体可点击。
- 色组编号可点击。
- 色组底部颜色条可作为该色组命中区域的一部分。
- 材料带、背景网格和色组之间的空隙不应触发色组选择。
- 相邻色组命中区域不能重叠。
- 命中区域与视觉图形分离维护，并满足工业触控的最小目标尺寸。

### 3.2 选中后的统一反馈

选中 PU3 后，至少同时反馈以下三处：

1. Canvas 中 PU3 使用青蓝色高亮描边，可增加轻微抬升或阴影变化。
2. 右侧面板标题变为“PU3 色组”。
3. 页面常驻区域显示“当前选中：03 / PU3”。

不建议只改变色组颜色，因为操作员可能无法判断这是选中态还是工艺颜色。

### 3.3 工艺颜色半圆弧

每个色组的工艺颜色采用“下版辊底部彩色半圆弧”表达：

- 半圆弧位于下版辊后侧或下沿，宽度约为下版辊直径的 `70%–85%`。
- 建议线宽约 `8–12px`，随 Canvas 缩放等比例适配。
- 与下版辊主体保留约 `2–4px` 间距，不遮挡辊筒轮廓和中心。
- 上、下辊筒主体保持金属灰蓝色，不把整只辊筒填成紫色、洋红色或黄色。
- 半圆弧只表示工艺颜色，不表示运行、警告、报警或选中状态。
- 运行/停止使用状态点与文字，警告/报警使用独立锚点和标签，选中使用青蓝描边。
- 总览模式用半圆弧简化表示油墨/工艺颜色；详情模式补充单个印刷单元原理图，说明油墨槽、刮刀和光电眼与当前 PU 的关系。
- 单个印刷单元原理图只在选中 PU 并展开详情后显示，不进入整机总览 Canvas，不增加 10 个色组的重复结构。
- 进入详情模式后默认展示原理图，不要求操作员额外点击“原理图”标签；这样单击色组后可以立即理解当前单元。
- 原理图与关键状态同时出现在详情首屏；检测曲线作为详情中的明确入口，需要查看波峰、波谷、参考线和检测窗时再进入。
- 原理图是工艺关系示意，不承诺机械尺寸、真实透视比例或可编辑的设备几何模型；机械尺寸和安装关系以后续设备数据为准。
- 原理图中的部件可以点击高亮并查看职责说明，但本版本不在图上直接执行启停、压力、速度、刮刀或油墨参数控制。
- 原理图中的颜色只表达工艺颜色和部件关系；运行、警告、报警、选中仍分别使用状态点/文字、报警锚点和青蓝描边表达。
- 半圆弧不设置独立拖动或编辑行为，点击该区域仍命中所属色组。

### 3.4 选中与跳转关系

最终统一规则如下：

```text
单击整机色组 03
    → 命中 PU3
    → 更新当前色组上下文
    → 展开右侧 PU3 详情

点击详情中的“查看 PU3 检测曲线”
    → 进入锁定标记
    → 自动显示 PU3 曲线、检测窗、偏差和信号状态
```

- 单击色组主体、编号或颜色半圆弧：只执行选中和详情展开，不直接跳页。
- 右侧详情提供明确的“查看 PU 检测曲线”文字按钮，点击后进入对应 PU 的锁定标记；这是 P0 的正式入口，也是鼠标、键盘和触摸用户都能发现的操作方式。
- 不提供双击进入锁定标记、双击提示或其他依赖双击的隐藏手势；双击不触发任何业务动作。
- PU1 仍可单击查看详情和原理图，但曲线入口禁用并显示“PU1 暂无锁定标记检测”。
- 设备处于停止、警告或报警状态时，仍允许进入对应 PU 查看页面。
- 跳转不能清除或确认原有报警。
- 从锁定标记页点击“返回整机”或通过主导航进入整机时，先处理未应用修改，再清除当前 PU、来源 PU 和报警定位上下文，恢复 `/overview` 整线摘要。
- 锁定标记页内部切换 PU 时，不强制自动返回整机页。

### 3.5 视图稳定性

不建议点击报警色组后自动旋转、缩放或移动整条设备图。建议只做：

- 当前色组高亮。
- 右侧详情同步更新。
- 报警锚点轻微强调。

工业现场需要保持设备空间位置稳定，自动移动视图可能使操作员失去整线方向感。

### 3.6 总览与详情两态

默认采用两种布局状态：

```text
总览模式：全宽整线 Canvas + 右侧窄摘要
详情模式：整线 Canvas + 右侧简化单元原理图与完整详情
```

- 总览模式用于快速查看放卷、10 个色组、收卷和整线走料。
- 首次进入且未选中色组时，窄摘要显示“请选择色组查看详情”；选中色组后才显示编号、PU、运行状态、报警状态和“详情”入口。
- 单击色组主体、对应 PU 的报警锚点或“详情”入口后，整线 Canvas 保持可见，右侧展开完整详情并默认显示当前 PU 简化原理图；单击不直接跳转页面。
- 右侧完整详情提供“查看 PU 检测曲线”文字按钮，点击后进入锁定标记。
- 不提供双击业务动作；进入锁定标记必须点击右侧明确的检测曲线按钮。
- 完整详情面板显示当前 PU 的关键状态、偏差、信号状态和后续操作入口。
- 新报警出现时不自动进入详情模式；只有用户点击 PU 报警锚点后才显示对应 PU 原理图和报警详情。
- 整机级报警没有对应 PU 时，保留整线 Canvas，并在右侧显示整机报警详情，不强行显示某个单元原理图。
- 详情展开时不自动旋转或飞行移动设备图，只切换主区域内容并重新计算布局适配。
- 点击“收起详情 / 返回总览”后清除当前 PU 和报警定位上下文，恢复全宽整线 Canvas 与整线摘要。

## 4. 报警显示优化

### 4.1 两层报警表达

顶部负责汇总，Canvas 负责定位：

```text
顶部：报警 / 停机级 1 / 活动报警 3 / 待确认 2
Canvas：PU3 信号异常、PU5 套色偏差超限、整机张力报警
```

### 4.2 状态表达建议

状态不能只依赖颜色，应同时使用文字或图形：

| 状态 | 建议颜色 | 建议辅助表达 |
| --- | --- | --- |
| 正常运行 | 绿色 | 绿色圆点 + “运行” |
| 警告 | 黄色/橙色 | 黄色提示点 + “警告” |
| 停机级报警 | 红色 | 红色菱形/锚点 + “停机” |
| 信号异常 | 紫色或蓝灰色 | 信号图标 + “信号异常” |
| 单元停止 | 中性灰 | 灰色状态点 + “停止” |

### 4.3 报警详情

点击 PU3 的报警标记后，右侧优先显示 PU3 的报警详情：

```text
PU3 报警
信号异常
发生时间：19:42:08
状态：活动 / 待确认

[查看检测曲线]
[确认报警]
```

不建议点击某个色组后先打开包含所有设备的报警列表，再让操作员重新寻找该色组。

### 4.4 确认和复位分离

必须明确区分：

```text
确认报警：我已经看到了这个报警
复位设备：故障已经处理，允许设备恢复
```

两个动作不能合并，避免出现“确认报警后设备自动恢复”的误操作。

## 5. 右侧详情面板优化

首次进入整机浏览且未选中色组时，右侧只显示窄摘要提示：

```text
请选择色组查看详情
```

单击色组后才显示具体 PU 的详情内容。

建议固定为三层信息：

### 第一层：当前对象

```text
PU3 色组
蓝紫色
运行中
光电眼在线
```

### 第二层：最重要的数据

```text
套色纵向偏差  +0.03 mm
套色横向偏差  −0.01 mm
版辊转速      120 rpm
```

### 第三层：扩展参数

```text
张力
刮刀压力
压印压力
干燥温度
油墨黏度
```

扩展参数可以放在“更多参数”或折叠区域，避免首屏堆叠过多数字。

### 5.1 详情模式中的单个印刷单元原理图

单击色组展开详情后，在详情区域默认提供当前 PU 的单元原理图。原理图用于“看懂当前单元”，不是把整机 Canvas 再画一遍，也不是新的控制面板。

#### 5.1.1 详情模式布局分区

详情模式采用“左图右信息”的固定分区，原理图和关键状态同时可见：

```text
┌──────────────────────────────────────┬────────────────────┐
│                                      │ 当前 PU 关键信息   │
│       单个印刷单元原理图              │ 运行状态           │
│ 材料带、版辊、油墨槽、刮刀、光电眼     │ 偏差 / 报警状态    │
│                                      │ 查看检测曲线       │
└──────────────────────────────────────┴────────────────────┘
```

- 右侧状态与操作区域使用约 `360–420px` 的固定范围，显示当前 PU、运行状态、关键偏差、信号状态、报警状态和“查看 PU 检测曲线”入口。
- 左侧原理图区域使用右侧状态区以外的剩余空间，不再额外使用 `60%–70% / 30%–40%` 的固定百分比分割，避免与详情侧栏宽度规则冲突。
- 在 1920×1080、16:9 目标分辨率下，原理图应占据主要可视区域，右侧状态区保持稳定宽度。
- 原理图不放入总览模式的窄摘要；总览模式只保留整线状态、当前选择提示和报警定位。
- 详情模式不再额外平铺第二张整线 Canvas；当前 PU 原理图是详情区域的唯一结构图。
- 在 1920×1080、16:9 目标分辨率下，原理图和右侧信息必须在同一首屏可见，不依赖横向滚动。
- 当可用宽度不足以维持左右分区时，先保持右侧关键状态和操作入口完整，再将原理图与右侧信息上下堆叠；不得把关键按钮缩成仅图标。
- 详情模式不得通过横向滚动解决空间不足；应优先缩短次要说明、减少非关键装饰，再切换为上下堆叠。
- 详情模式收起后恢复“全宽整线 Canvas + 窄摘要”，不保留原理图占位，也不改变整线空间位置。

建议固定展示以下关系：

```text
承印材料 / 材料带 → 压印辊与版辊 → 油墨槽与刮刀 → 光电眼检测点
```

界面要求：

- 详情模式打开时默认落在“单元原理图”视图；不需要先点击标签或按钮才能看到结构关系。
- 默认显示当前 PU 编号、工艺颜色和材料运行方向。
- 用简化结构表示材料带、上方压印辊、下方版辊、油墨槽、刮刀和光电眼。
- 下版辊继续使用工艺颜色半圆弧，辊筒主体保持金属灰蓝色。
- 用一条轻量的“检测信号”关系线指向光电眼，帮助理解曲线数据从哪里来。
- 点击部件时只高亮该部件并显示一句职责说明；不要求操作员在原理图中拖动、旋转或编辑设备。
- 结构图不显示全部实时参数，关键数值仍放在右侧详情的状态和数据区域。
- 报警只在对应部件或详情状态区域表达，不通过给整个原理图染红来表达。
- 原理图与“查看 PU 检测曲线 / 进入锁定标记”入口并列，二者互不替代：原理图用于理解设备关系，曲线用于确认检测位置和偏差。
- 从锁定标记返回详情时，优先恢复当前 PU 的详情上下文，并默认回到原理图；如果产品后续需要保留上次标签状态，应单独定义，不在本版本扩展。
- PU1 没有锁定标记时，仍可查看 PU1 原理图；点击曲线入口时提示“PU1 暂无锁定标记检测”。

不建议在本版本加入以下内容：

- 真实机械尺寸、复杂 3D 透视和自由旋转。
- 在原理图中直接修改压力、速度、张力、油墨黏度或刮刀位置。
- 让原理图承担报警确认、设备复位或检测窗编辑。
- 在 10 个色组总览中同时平铺 10 张单元原理图。

操作员首先需要知道的是：

```text
当前是谁
是否正常
偏差是多少
下一步能做什么
```

## 6. 色组状态带

可在 Canvas 下方增加简洁状态带：

```text
01 正常 | 02 停止 | 03 正常 | 04 警告 | 05 正常 | ...
```

设计要求：

- 不替代 Canvas，只作为快速浏览辅助。
- 每个状态项可以点击，并执行与 Canvas 相同的选中逻辑。
- 报警色组使用更高对比度，正常色组降低视觉权重但仍保持可读。
- 状态带中必须同时显示编号和文字，不能只有色块。

## 7. 轻量筛选

建议只提供少量、容易理解的筛选：

```text
全部
仅报警
```

“仅报警”视图下，只突出 warning 和 stop 级报警色组，正常色组降低视觉权重。停止但无报警、信号异常等状态仍保留在“全部”视图中。不要引入更多组合筛选，避免增加现场人员的理解成本。

## 8. 速度与设备操作

本版本整机页以速度查看为主，不把总览页变成速度控制面板：

- P0：显示当前速度、目标速度、运行模式和允许范围。
- P1：再考虑速度预设、目标速度修改、手动升速和降速。
- 所有 P1 操作都必须显示当前值、目标值、单位和执行反馈。

### 8.1 速度信息

速度区域建议同时显示：

```text
当前速度：24.0 m/min
目标速度：36.0 m/min
运行模式：自动
允许范围：0–150 m/min
```

### 8.2 操作方式

- 预设速度：24 / 36 / 120 / 150 m/min。
- 手动升速、降速：按住执行，松手停止。
- 目标速度修改：使用步进器或滑块。
- 修改关键参数时同时显示当前值、目标值和单位。
- 可能造成停机或速度变化的操作，必须有明确的执行反馈。
- 升速、降速不建议只使用没有文字说明的小图标按钮。

## 9. 数据和异常状态

整机页建议明确覆盖以下状态：

- 整机正常运行。
- 整机停止。
- 单个 PU 停止但整机仍运行。
- PU 警告。
- PU 停机级报警。
- 整机停机级报警。
- 光电眼信号中断。
- 数据源暂时没有更新。
- 当前色组暂无锁定标记检测。
- 当前没有选中色组。
- 页面切换中或数据恢复中。

以下概念必须保持区分：

```text
设备停止 ≠ 信号中断
信号中断 ≠ PU 停止
报警已确认 ≠ 故障已恢复
整机运行 ≠ 所有 PU 都正常
```

### 9.1 数据新鲜度显示

- 正常状态下只显示“数据正常”，不在顶部长期堆叠更新时间字段。
- 整机快照连续超过 `2000ms` 未更新时，显示“整机数据延迟”，并在详情中显示最后更新时间。
- 当前 PU 曲线连续超过 `2000ms` 未收到新帧时，显示“信号中断”，并保留最后一帧。
- “整机数据延迟”和“信号中断”分别表达整机数据源与当前 PU 信号源问题，不能合并为普通停止。

## 10. 返回和跨页面上下文

锁定标记页可以显示来源提示：

```text
来源：整机浏览 → 色组 03 → PU3
```

返回整机页后：

- 先处理未应用的检测窗修改；
- 清除当前 PU、来源 PU 和报警定位上下文；
- 地址恢复为 `/overview`，右侧恢复整线摘要；
- 不保留原 PU 高亮，避免下一次操作误用旧上下文。

锁定标记页内部切换 PU 时，只更新当前曲线和 URL；不会自动返回整机页。

## 11. 触控与可读性

- 普通操作目标不小于 48×48px，关键操作建议 56px 高。
- 关键业务流程不能依赖鼠标悬停。
- 触控和鼠标都应有等价操作。
- 点击后立即出现高亮、按压态或状态提示。
- 重要状态同时使用颜色、图标和文字表达。
- 报警动效低频、稳定，不使用全屏高频闪烁。
- 正常色组不使用过强饱和色，确保报警色组突出。
- 文字和数字在 1920×1080 工业触摸屏上保持清晰可读。

## 12. 不建议采用的设计

- 自由旋转 2.5D 设备。
- 报警时全屏高频闪烁。
- 设备状态只用颜色表达。
- 只有点击很小的编号文字才能操作色组。
- 点击后没有任何即时反馈。
- 所有参数都使用小数字输入框平铺。
- 正常色组使用过强颜色，导致报警不突出。
- 报警后自动移动或旋转视图。
- 将“确认报警”和“复位设备”合并。
- 把信号中断显示成普通停止。
- 让整机 Canvas 承担所有文字、按钮和报警详情。

## 13. 时间有限时的实施顺序

如果开发时间有限，建议按以下顺序实现：

1. 色组完整区域可点击，单击 03 打开 PU3 详情。
2. Canvas、右侧面板和页面标题三处同步显示选中态。
3. 运行状态和报警状态分开表达。
4. 右侧提供“查看 PU3 检测曲线”入口；不使用双击快捷进入锁定标记。
5. 增加数据新鲜度和信号中断提示。
6. 补充色组状态带。
7. 补充详情面板分层和轻量筛选。
8. 最后再考虑更复杂的速度操作和工业化扩展。

## 14. 评审时需要重点观察的问题

- 操作员能否在 3 秒内判断整机是否运行、当前车速和是否报警？
- 能否一眼找到异常色组，而不需要先打开多个菜单？
- 点击色组后，是否明确知道当前选中的是哪个 PU？
- 单击 03 是否只打开 PU3 详情，点击详情中的检测曲线按钮是否进入 PU3 锁定标记，双击是否不触发业务动作？
- 设备停止、信号中断、报警待确认是否有清晰区别？
- 报警确认后，界面是否仍然表达故障是否恢复？
- 触控时是否容易点中正确色组，是否存在相邻色组误触？
- 设备图是否保持稳定，没有因为报警或点击而自动改变视角？

本节合并原第二版优化方案中的代码复审内容，用于指导后续迭代。它是产品与工程的共同验收基线，不改变前文已经确认的交互规则。

### 15.1 复审结论

当前版本已经具备可演示的主流程：整机 2.5D Canvas、印刷单元详情、锁定标记曲线、检测窗编辑、报警确认/复位和可复现模拟数据源。下一轮的重点不再是“能否显示”，而是：

- 状态是否可信，尤其是待确认、已恢复和待复位状态；
- 检测窗修改是否可撤销，正式值和草稿值是否严格分离；
- 报警是否可以从产生一直闭环到人工启动；
- 1920×1080 和 1280×720 下关键动作是否始终可达；
- 页面、URL、来源 PU 和当前 PU 是否保持一致；
- 键盘、弹层和触控操作是否都有明确反馈。

当前能力与后续关注点：

| 能力 | 当前判断 | 后续关注 |
| --- | --- | --- |
| 整机浏览 | 已实现 2.5D Canvas、状态带和详情面板 | 保持整线定位稳定，补充小屏布局验证 |
| PU 详情 | 已实现参数、原理图、报警状态和操作区 | 关键状态与主动作首屏可达 |
| 锁定标记 | 已实现曲线刷新、冻结、信号提示和检测窗操作 | 统一草稿事务和离开保护 |
| 报警模型 | 已有活动、确认、恢复、复位和启动字段 | 统一状态派生和统计口径 |
| 数据源 | 机台源、信号源和计算逻辑已分层 | 保持数据源不直接操作组件或 DOM |
| 路由上下文 | 支持 `?pu=` 和来源提示 | 当前 PU、来源 PU、URL 和返回行为一致 |
| 键盘与弹层 | 已有基础关闭和焦点逻辑 | 继续完善安全边界和可访问性 |

### 15.2 状态域与不变量

后续实现可以继续使用一个 Store，但应按以下五个概念域管理状态，避免只读浏览、草稿编辑和报警锁存互相隐式修改：

```text
machineState       设备、色组、速度、张力、运行状态
alarmState         报警列表、活动数、待确认数、待复位数、最高级别
navigationState    当前页面、来源 PU、当前 PU、URL 参数
windowEditorState  编辑模式、草稿、进入编辑前快照、脏状态、应用时间
uiState            抽屉、原理图弹层、确认条、Toast、焦点返回目标
```

必须保持以下不变量：

1. `selectedStationId` 只表示当前正在查看的 PU，不代表正在编辑。
2. `sourceStationId` 只记录刚进入页面时的来源 PU；用户主动切换 PU 后清除。
3. `state.windows[id]` 只保存正式检测窗；编辑中的值只能放在草稿对象中。
4. 选中、查看详情、打开曲线和刷新信号等只读动作不得创建草稿。
5. 只要存在待确认、待复位或其他阻塞原因，顶部不得显示完全正常。
6. URL 中的 `?pu=`、导航状态和页面标题中的当前 PU 必须一致。
7. 所有主动作必须有可见按钮，不依赖双击、长按等隐藏手势。

### 15.3 操作安全与键盘边界

检测窗的 Enter 快捷键只能作为编辑区内“应用检测窗”的等价操作，不能让页面空白区、导航按钮或普通报警控件产生保存副作用：

- 只有处于 `creating` 或 `editing` 状态时才响应 Enter；
- 焦点必须位于检测窗编辑区，焦点位于按钮、链接、输入框、弹层或页面空白区时不拦截；
- 新建和替换草稿都必须保留可见的“应用检测窗”按钮；
- Escape 在编辑区取消草稿或关闭确认条，不绕过未应用修改保护；
- 组件卸载时移除监听，优先使用组件根节点事件；
- 应用成功后显示 PU、数据坐标和时间，例如 `PU8 检测窗已应用 · x 171–291 · 16:24:30`。

### 15.4 报警抽屉与报警语义

报警抽屉采用固定头部、独立滚动列表和固定底部动作区：

```text
报警抽屉
├── 标题与关闭
├── 活动 / 待确认 / 待复位统计
├── 需处理 / 活动 / 待确认 / 待复位筛选
├── 报警列表（独立滚动）
└── 整机启动或底部主操作
```

设计要求：

1. 抽屉使用纵向 Flex，列表区域 `flex: 1; min-height: 0; overflow-y: auto`。
2. 标题、关闭、统计、筛选和整机启动始终可见；背景页面不跟随滚动。
3. 新报警到达时不强制把用户正在查看的列表跳回顶部。
4. 每条报警展示级别、来源 PU、生命周期、发生/恢复时间和可用动作。
5. 报警筛选至少包含“需处理、活动、待确认、待复位”；“需处理”覆盖活动报警、待确认、待复位、信号中断和联锁停止。
6. 报警状态派生统一使用同一套规则，组件不各自拼接状态文案。

推荐状态优先级：

```text
活动停机级报警
→ 已恢复但待复位的停机报警
→ 活动警告
→ 任意待确认报警
→ 所有报警已闭环 / 正常
```

完整生命周期为：

```text
活动 / 待确认
    → 活动 / 已确认
    → 已恢复 / 待复位
    → 已复位 / 已关闭
    → 归档
```

确认只表示操作员已经看到，不能改变故障是否活动；复位只对条件已恢复且已确认的停机报警开放；复位后仍需人工启动。

### 15.5 检测窗草稿事务

普通查看、PU 切换和信号刷新不得自动创建草稿。推荐统一使用以下事务：

```text
查看正式检测窗
    ↓ 点击新建 / 编辑
创建草稿 + 保存编辑前快照
    ↓ 拖动 / 缩放 / 左右移动
只修改 draftByStation[id]
    ↓ 应用
校验 → 写入正式窗口 → 记录变更 → 清理草稿
    ↓ 取消
恢复快照 → 清理草稿
```

具体约束：

- 正式检测窗与草稿检测窗不能共用同一对象引用；
- 拖动、缩放、左移和右移都只能修改草稿；
- `dirty` 由草稿与编辑前快照的结构化比较得出；
- 应用前校验坐标顺序、最小宽高、数据量程、信号有效性和权限状态；
- 应用、取消、切换 PU、返回整机和关闭页面使用同一套未应用修改保护；
- 偏差默认继续使用正式检测窗，草稿若需要预览必须明确标记为“预览计算”。

建议统一文案：

| 场景 | 文案 | 说明 |
| --- | --- | --- |
| 无正式窗口 | 当前未设置检测窗 | 创建后开始用于偏差计算 |
| 新建草稿 | 新建草稿未应用 | 应用后开始用于偏差计算 |
| 替换草稿 | 替换草稿未应用 | 当前仍使用原检测窗计算 |
| 编辑中 | 检测窗有未应用修改 | 应用或取消后才能离开 |
| 已应用 | 当前检测窗已应用 | 显示应用时间和操作人 |
| 信号中断 | 信号中断，保留最后有效帧 | 暂停偏差更新 |
| 信号恢复 | 信号恢复中 | 等待连续有效帧后恢复计算 |

### 15.6 导航、URL 与上下文

PU 切换应统一通过导航函数完成：

1. 校验 PU 是否存在；
2. 更新 `selectedStationId`；
3. 同步 URL 的 `?pu=PU8`；
4. 更新标题、页签、详情和曲线数据；
5. 保持返回行为可预测。

从整机进入锁定标记时写入 `sourceStationId`，页面内主动切换 PU 后清除来源提示；当前查看对象始终使用 `selectedStationId`。从锁定标记返回整机时，先处理未应用修改，再清除 PU 和报警上下文，恢复整线摘要。

### 15.7 1920×1080 与 1280×720

1920×1080 继续作为主设计基准，保留顶部状态、中部工艺路径、右侧详情和底部速度/张力/事件信息。1280×720 不应简单缩放 1920 布局，应采用紧凑断点：

- 顶部只保留工单、速度、整机状态和报警摘要；
- 详情和锁定标记的内容区独立滚动，主动作区吸底或 sticky；
- 首屏优先显示 PU 名称、运行/报警状态、阻塞原因、四项关键参数和主动作；
- 次要参数放入“更多参数”；
- PU 页签保持单行文本，宽度不足时横向滚动，不进行单字换行；
- 报警抽屉列表独立滚动，不带动背景页面；
- 1920×1080 下主要任务无需页面级滚动，1280×720 下“应用/取消”“确认/复位”等动作仍可见。

### 15.8 辅助能力与可访问性

任何视觉上可点击的入口都必须有可观察结果。设置入口未实现时，应隐藏、禁用并说明原因，或提供明确的“设置功能暂未开放”反馈。

报警抽屉、原理图弹层和确认弹层应统一具备：

- `role="dialog"`、`aria-modal="true"` 和标题关联；
- 打开后焦点进入弹层，Tab 焦点不跑出弹层；
- Escape 关闭非危险弹层；有未应用修改时先进行保护提示；
- 关闭后焦点返回触发按钮；
- 遮罩点击关闭行为按风险等级统一。

每条报警提供与来源匹配的显式定位动作：单元报警“定位 PU7”、信号报警“查看 PU7 曲线”、整机报警“查看整机状态”。定位不能替代确认和复位按钮。

## 17. 后续实施顺序与回归验收

### 第一阶段：操作安全与报警可达性

1. 收敛 Enter 快捷键边界；
2. 抽屉固定头部、独立滚动；
3. 统一报警生命周期、顶部最高状态和分项统计；
4. 将“仅报警”统一为“需处理”。

### 第二阶段：检测窗事务化

1. 移除普通查看和信号刷新产生的自动草稿；
2. 统一新建、替换、拖动、缩放和左右移动的草稿机制；
3. 增加应用、取消、离开保护和变更反馈；
4. 修正文案、正式值和草稿值的计算边界。

### 第三阶段：导航、小屏和辅助能力

1. 同步 PU 与 URL，分离来源 PU 与当前 PU；
2. 优化 1280×720 的详情、锁定标记和页签布局；
3. 增加报警来源定位；
4. 处理设置入口、弹层焦点和键盘闭环；
5. 保持单击导航，不实现双击快捷跳转。

### 回归验收重点

- 待确认或待复位报警存在时，顶部不显示绿色“正常”；
- 活动、确认、恢复、复位和归档状态可区分；
- 需处理筛选包含报警、待复位、信号中断和联锁停止；
- 仅查看 PU 不产生草稿，拖动和移动只修改草稿；
- 应用、取消和离开保护始终可达；
- PU 切换后 URL、标题和曲线对象一致；
- 双击 PU 不触发业务跳转或隐藏动作；
- 1920×1080 主要任务无需页面滚动，1280×720 关键动作首屏可见；
- 抽屉和弹层支持关闭按钮、Escape 和正确的焦点返回。
