# VISU·19 Web HMI 客户演示流程

> 文档用途：客户现场功能演示与讲解提词  
> 建议时长：标准版 `8–10 分钟`，精简版 `5 分钟`  
> 目标环境：`1920×1080`、16:9 工业触摸屏或等比例浏览器窗口  
> 演示范围：整机浏览、PU 详情、单元原理图、锁定标记、检测窗、信号异常、报警闭环  
> 数据说明：当前版本使用前端可复现模拟数据，未来可替换为 PLC、WebSocket 或设备接口数据源

## 1. 演示口径

本次演示不按按钮逐个介绍，而是围绕一条完整的操作员工作流展开：

```text
查看整线状态
→ 定位具体 PU
→ 查看单元结构与关键参数
→ 进入该 PU 的锁定标记
→ 设置检测窗并观察套色偏差
→ 模拟信号异常与恢复
→ 处理报警并恢复设备
```

客户应在演示结束后明确感受到以下价值：

1. 在一个屏幕内快速判断整机是否运行、当前车速和哪里需要处理。
2. 从整线设备直接定位到具体 PU，不需要在多个页面重新查找对象。
3. 检测窗、参考线和偏差数据之间关系清楚，操作结果可确认、可取消。
4. 信号中断、设备停止、普通警告和停机级报警不会混为一谈。
5. 报警确认、条件恢复、复位和启动相互分离，避免误操作。

### 1.1 当前版本的最终交互规则

- 单击 PU：选中该 PU，并立即打开右侧详情。
- 不使用双击跳转，避免工业触摸屏上的时序歧义和误触。
- 进入锁定标记：点击详情中的“查看 PU 检测曲线”文字按钮。
- PU1 可以查看详情和原理图，但没有锁定标记检测入口。
- 打开 PU 详情后，整线 Canvas 始终保留；右侧默认显示简化单元原理图。
- 点击原理图“展开”后，在弹层中查看完整原理图，不挤压整线 Canvas。
- 关闭 PU 详情或从锁定标记返回整机后，回到未选中 PU 的整线总览状态。
- 速度、版辊偏移和启停操作均为当前前端演示规则，不应对客户表述为已连接真实设备。

> 说明：《产品优化》中的部分“双击进入锁定标记、详情时用单元原理图替换整线 Canvas、返回后保留选择”等内容属于早期方案。本演示统一以当前《产品计划》和实际实现为准。

## 2. 演示前准备

### 2.1 环境检查

演示前执行：

```bash
npm run test:acceptance
npm run build
npm run dev
```

确认：

- 验收脚本显示 `acceptance checks passed`。
- 构建显示 `built successfully`。
- 浏览器缩放为 `100%`。
- 页面以 `1920×1080` 或相同比例展示。
- 从 `/overview` 进入整机浏览页。
- 刷新后等待约 2 秒，确认车速、时间和设备状态持续更新。

### 2.2 演示数据准备

- PU2 默认已有一个检测窗，可用于快速展示“已应用检测窗”和偏差表。
- PU3 默认没有检测窗，适合演示“新建草稿 → 调整 → 应用”的完整流程。
- 整机和报警每次刷新从相同初始状态开始，关键状态每 90 秒推进一次；PU7 初始会出现停机级报警。
- 信号中断可通过锁定标记页的“模拟信号中断（演示）”主动触发。
- 检测窗会在当前浏览器会话中保存；正式演示前不要删除 PU2 的默认检测窗。

### 2.3 演示注意事项

- 不要双击 PU；统一使用单击和明确文字按钮。
- 不要在检测窗存在未应用草稿时直接切换 PU；应先选择“应用”或“取消修改”。
- 演示报警前建议先回到 `/overview` 并刷新一次，以便从 PU7 的初始停机报警开始演示。
- “设置”入口当前尚未开放，不纳入客户功能演示。
- 不演示报警历史、权限、操作审计和真实 PLC 控制，这些属于后续接入范围。

## 4. 标准演示详细步骤与话术

### 步骤一：开场说明

操作：打开整机浏览页，暂时不要点击任何 PU。

建议话术：

> 这是面向 1920×1080 工业触摸屏重新设计的 Web HMI。我们没有简单拉伸原来的 4:3 页面，而是按照操作员的使用顺序重新组织信息：先判断整线状态，再定位单元，最后进入检测和处理流程。当前数据由前端场景脚本模拟，数据接口层可以在后续替换为真实设备数据源。

需要强调：

- 当前是固定视角的参数化 2.5D 工艺视图，不是自由旋转的 3D 模型。
- 固定视角能保持放卷、色组和收卷的空间位置稳定，更适合工业现场快速识别。

### 步骤二：展示整线总览

操作顺序：

1. 指向顶部状态栏。
2. 指向中央 2.5D Canvas。
3. 指向 Canvas 下方的 01–10 状态带。
4. 指向底部速度、卷材、张力和最新事件区域。
5. 可点击“全部 / 需处理”，展示色组轻量筛选。

建议话术：

> 顶部只保留整线级高优先级信息，包括工单、幅宽、实际线速度、整线状态、报警汇总和时间。中间按工艺顺序完整展示放卷、10 个印刷单元和收卷，走料方向始终可见。色组底部的彩色半圆弧只表示工艺颜色，运行、警告、报警和选中分别使用独立的状态点、文字、报警标记和青蓝描边，避免颜色语义混淆。

> 下方状态带可以快速扫查 10 个 PU，也可以切换到“需处理”，只查看当前需要操作员关注的单元。底部显示实际速度、目标速度、加减速时间、活动轴、计长、摆臂位置和张力，不需要进入多个设置页面才能完成基本判断。

可选速度演示：

1. 点击 `36 m/min` 速度预设。
2. 因为与当前目标速度差值较大，界面出现调整确认条。
3. 点击“确认调整”。
4. 观察目标速度立即更新、实际速度逐步变化和 Toast 反馈。

说明话术：

> 速度变化不是无反馈的瞬时点击。较大目标变化会先显示当前值、目标值和单位，并要求明确确认；这里是前端模拟目标速度，真实接入时会发送设备指令并等待 PLC 回执。

### 步骤三：从整线定位到 PU3

操作顺序：

1. 单击 Canvas 中的 `03` 色组，或单击状态带中的 `03`。
2. 观察 PU3 青蓝色选中描边。
3. 观察右侧立即展开 `PU3 印刷单元` 详情。
4. 指出整线 Canvas 仍然保留，没有被单元图替换。
5. 查看状态、光电眼、纵向/横向偏差、版辊转速和段间张力。
6. 展开“更多参数”，查看刮刀压力、压印压力、干燥温度和油墨黏度。

建议话术：

> 单击只负责建立当前 PU 上下文并打开详情，不直接跳页，也不依赖双击。Canvas 高亮、右侧标题和参数会同步更新。整线结构继续保留，操作员查看单元时不会失去自己在整条生产线中的位置。

### 步骤四：展示单元原理图

操作顺序：

1. 在右侧简化原理图中指出材料带、压印辊、版辊、油墨槽、刮刀和光电眼。
2. 点击“展开”。
3. 在完整原理图中依次点击版辊、刮刀或光电眼。
4. 观察部件高亮和职责说明。
5. 关闭原理图弹层。

建议话术：

> 简图用于解释当前印刷单元的结构和检测关系，不是机械尺寸图，也不是新的控制面板。点击部件只展示职责说明，不会直接执行启停或参数修改。需要看更细的信号和偏差时，再通过明确入口进入锁定标记。

### 步骤五：进入 PU3 锁定标记

操作顺序：

1. 点击右侧“查看 PU3 检测曲线”。
2. 观察页面顶部显示“已从整机 PU3 进入”。
3. 观察 PU3 标签自动选中。
4. 指出曲线标题中的 PU3、1200 点和 500ms 刷新频率。

建议话术：

> 这里没有让操作员进入页面后再次查找 PU。整机页选中的 PU3 会作为上下文带入锁定标记，曲线、检测窗、偏差和信号状态都切换到同一个对象。

在曲线区重点说明：

- 每帧包含 1200 个采样点，每 500ms 接收一帧。
- 曲线包含首色、前色和本色对应的波峰、波谷与参考位置。
- 底部颜色条、参考线和检测窗使用不同视觉层级，不会互相混淆。
- 右侧同时显示数据坐标、纵向偏差（MD）、横向偏差（CD）、预警阈值和停机阈值。

### 步骤六：完成检测窗事务流程

推荐在 PU3 上演示新建流程。

操作顺序：

1. 点击“新建检测窗”。
2. 界面生成“新建草稿未应用”，此时偏差计算尚未正式使用该草稿。
3. 在曲线上拖动检测窗主体，或拖动边缘/角点，使窗口覆盖明显波峰或波谷。
4. 使用“检测窗左移 / 检测窗右移”完成小步微调。
5. 指向右侧 `x` 和 `y` 数据坐标，说明它们随操作更新。
6. 点击“应用检测窗并开始计算”。
7. 观察草稿提示消失，检测窗变为已应用状态，偏差表开始使用该窗口计算。

建议话术：

> 检测窗采用草稿和已应用两层状态。调整过程中不会立即覆盖正在使用的检测窗，操作员可以确认后应用，也可以取消修改。窗口保存的是曲线数据坐标，不是屏幕像素，所以页面尺寸、缩放和平移变化后，检测区域仍然对应原来的采样位置。

如需演示替换保护：

1. 点击“新建替换检测窗”。
2. 确认“保留原检测窗并创建替换草稿”。
3. 移动草稿后点击“取消修改”。
4. 说明原有已应用检测窗没有被破坏。

不建议在主流程中删除检测窗；删除功能可在客户主动询问时展示，并需要二次确认。

### 步骤七：展示冻结、视口和版辊偏移

从以下功能中选择 1–2 个展示即可，不必全部操作。

#### 冻结曲线

1. 点击“冻结曲线”。
2. 观察画面停止更新，并显示冻结时间。
3. 点击“恢复实时曲线”。

话术：

> 冻结只停止当前画面的视觉刷新，后台仍继续接收数据。操作员可以稳定观察某一帧，但不会误以为采集已经停止。

#### 曲线视口

1. 点击“放大”。
2. 点击“左移 / 右移”。
3. 点击“重置曲线视图”。

话术：

> 缩放和平移只改变查看范围，检测窗仍以数据坐标保存，不会因为视口变化而丢失或漂移。

#### 模拟版辊偏移

1. 点击一次“版辊偏移 +0.01 mm”。
2. 观察偏移读数和横向偏差变化。
3. 点击“恢复 0.00 mm”。

话术：

> 这里用前端模拟值展示调机反馈。真实接入后，操作需要结合设备权限、互锁和 PLC 回执，当前版本不把它描述成真实机械控制。

### 步骤八：模拟信号中断与恢复

操作顺序：

1. 点击“模拟信号中断（演示）”。
2. 等待超过 2 秒。
3. 观察状态变为“信号中断”。
4. 观察曲线仍保留最后一帧，偏差显示为 `—`，并产生光电眼信号异常报警。
5. 点击“恢复模拟信号”。
6. 观察状态先进入“信号恢复中”。
7. 等待连续 2 帧有效数据后恢复为“实时”，偏差重新开始计算。

建议话术：

> 信号中断不等于设备停止。系统不会把没有收到的数据画成零值或空白来伪装正常，而是保留最后一帧并暂停偏差结论。恢复后也不会收到一帧就立刻判定正常，而是经过连续有效帧确认后再恢复计算。

### 步骤九：演示报警处理闭环

为了稳定展示 PU7 停机级报警，建议按以下顺序开始这一段：

1. 先点击“返回整机”。
2. 刷新 `/overview`。
3. 刷新后 4 秒内点击顶部报警汇总，打开“报警处理”抽屉。

操作与说明：

1. 指出顶部统计：活动、待确认、待复位。
2. 指出筛选：需处理、活动、待确认、待复位。
3. 找到 `PU7 · 凹版辊驱动停机`。
4. 观察报警最初为“活动 / 待确认”，复位按钮不可用。
5. 点击“确认报警”。
6. 强调确认后报警条件可能仍然存在，设备不会自动恢复。
7. 等待模拟条件恢复，报警进入“已恢复 / 待复位”。
8. 点击“复位报警”，该报警从当前需处理列表移除。
9. 关闭报警抽屉，单击 PU7 打开详情。
10. 点击“启动 PU7”，再点击二次确认中的“确认”。

建议话术：

> 这四个状态是分开的：确认表示“操作员已经看到”；恢复表示“故障条件已经消失”；复位表示“允许清除停机锁存”；最后还需要人工启动。系统不会因为确认报警或故障条件恢复就自动启动设备。

```text
报警产生
→ 人工确认
→ 条件恢复
→ 单条复位
→ 人工启动
→ 运行
```

补充说明：

- 普通警告不会直接阻止整机启动。
- PU 级停机报警只阻止对应 PU。
- 整机级停机报警会阻止整机启动。
- 光电眼信号中断影响对应 PU 的测量可信度和启动条件，但不要求停机级复位。
- 如果演示过程中整机进入停止状态，报警抽屉底部会显示“启动整机”；点击后仍需二次确认。

### 步骤十：返回总览并总结

操作：返回整线总览，保持页面停留在完整整机 Canvas。

建议话术：

> 整个流程从整线状态开始，经过 PU 定位、结构理解、曲线检测、窗口设置、异常识别和报警处理，最后回到整线总览。界面使用统一的数据模型驱动 Canvas、详情、报警和曲线状态，后续接入真实设备时主要替换数据源和指令回执，不需要重新组织操作流程。

最后总结三个设计价值：

1. **看得快**：全局信息、整线 Canvas 和色组状态带分层展示。
2. **定位准**：整机 PU、详情、锁定标记和报警使用同一个 PU 上下文。
3. **操作稳**：检测窗草稿、报警生命周期、速度确认和启动确认降低误操作风险。

## 5. 五分钟精简演示版

客户时间有限时，只演示以下主链路：

### 00:00–00:30：产品定位

- 1920×1080 工业触摸屏 Web HMI。
- 固定 2.5D 工艺视图，完整展示放卷、10 个 PU 和收卷。
- 当前使用前端模拟数据，可替换真实数据源。

### 00:30–01:30：整机总览与 PU 详情

- 展示顶部车速、整线状态和报警汇总。
- 展示 Canvas 走料方向、工艺色半圆弧和状态带。
- 单击 PU3，展示右侧简化原理图和关键参数。

### 01:30–03:20：锁定标记与检测窗

- 点击“查看 PU3 检测曲线”。
- 说明 1200 点、500ms、首色/前色/本色参考线。
- 新建检测窗草稿，拖动到波峰区域并应用。
- 指出数据坐标和偏差表。

### 03:20–04:10：信号中断

- 点击模拟信号中断，说明保留最后一帧和偏差显示 `—`。
- 点击恢复，说明连续有效帧确认机制。

### 04:10–05:00：报警与总结

- 打开报警处理抽屉。
- 说明“确认、恢复、复位、启动”四个独立动作。
- 总结整线定位、跨页面上下文和工业安全反馈。

## 6. 客户常见问题与回答建议

### 6.1 为什么不用完整 3D？

建议回答：

> 当前目标是帮助操作员快速判断整线状态和定位 PU。固定 2.5D 视图不会因旋转产生遮挡，也能减少模型资源和运行成本。未来如果存在维修拆解或空间巡检需求，可以在独立场景增加 3D，而不影响当前生产操作主界面。

### 6.2 Canvas 上的 10 个 PU 是写死的吗？

建议回答：

> 不是逐个写死绘制。色组数量、颜色、状态和位置由设备数组和参数化几何生成，后续可以按照不同机型调整数量、色序和间距。

### 6.3 检测窗缩放后为什么不会偏移？

建议回答：

> 系统保存的是采样点和信号强度对应的数据坐标，不是浏览器屏幕像素。显示时再根据 Canvas 尺寸和视口转换到屏幕坐标，所以缩放、平移或分辨率变化后仍对应同一段信号。

### 6.4 曲线冻结后还在接收数据吗？

建议回答：

> 仍然接收。冻结只锁住当前显示帧，后台最新帧继续更新；恢复时会切回最新有效数据。

### 6.5 报警确认后为什么不能直接恢复？

建议回答：

> 确认只表示操作员已经看到报警，不代表故障消失。停机级报警还需要等待条件恢复、执行复位，最后由人工启动，避免设备在人员处理故障时自动运行。

### 6.6 当前是否已经连接真实设备？

建议回答：

> 当前版本用于验证界面、交互、Canvas 性能和业务状态模型，数据由可复现的前端脚本产生。数据源与界面已经分层，后续可将模拟源替换为 PLC 网关、WebSocket 或其他设备接口，并补充权限、互锁和指令回执。

### 6.7 为什么 PU1 不能进入锁定标记？

建议回答：

> 当前业务规则中 PU1 作为首色基准单元，没有对应的锁定标记检测曲线。它仍可以查看结构和运行参数，但曲线入口明确禁用，避免进入无意义页面。

## 7. 现场异常备用方案

| 现场情况 | 处理方式 | 讲解口径 |
| --- | --- | --- |
| 当前没有活动报警 | 刷新 `/overview`，4 秒内打开报警抽屉 | 使用可复现报警场景，不依赖随机事件 |
| PU7 报警仍活动，复位不可用 | 先确认，等待条件恢复 | 复位受故障条件和确认状态约束 |
| 整机已停止，PU 无法启动 | 先在报警抽屉启动整机，再启动 PU | 整机状态是 PU 启动的前置条件 |
| PU3 已存在之前保存的检测窗 | 演示“新建替换检测窗”，或切换未设窗 PU | 原窗口在草稿应用前继续有效 |
| 信号恢复后偏差没有立刻出现 | 等待连续 2 帧有效数据 | 恢复需要稳定性确认，不是一帧即恢复 |
| 切换 PU 时提示未应用修改 | 选择应用或取消，再继续切换 | 防止草稿在离开页面时静默丢失 |
| 客户询问真实设备控制 | 明确当前为前端模拟，不现场承诺已接 PLC | 后续通过数据源、指令、权限和互锁层接入 |

## 8. 不建议在主流程中演示的内容

- 双击 PU 跳转，因为当前版本已取消该操作。
- 连续删除多个检测窗，容易破坏后续演示准备状态。
- 长时间反复拖动和缩放曲线，容易弱化业务主线。
- 报警历史、权限和审计，因为当前版本未实现。
- 设置页面，因为当前入口尚未开放。
- 把模拟速度、版辊偏移或启动操作描述成真实设备控制。
- 深入讲解所有 P0/P1/P2 内部分级；面对客户应优先讲业务价值和实际流程。
