# VISU·19 Web HMI 审查解决方案

> 统一口径：本文包含历次审查方案与实施建议。与《产品计划》的最终规则冲突时，以《产品计划》及当前实际实现为准：单击 PU 打开详情，使用显式文字按钮进入锁定标记；不使用双击业务动作；详情打开后整线 Canvas 保持可见；20 秒录屏为可选补充交付，不是代码验收门槛。

## 1. 方案目标

本方案用于解决《审查结果.md》中列出的 P0/P1 问题，使当前 Web HMI 从“可运行演示版”提升为：

1. 满足产品计划 P0 提交门槛；
2. 在 1920×1080 工业触摸屏基准下无滚动、无内容截断；
3. 完成整机页到锁定标记页的一次操作联动；
4. 让整机状态、曲线刷新、报警和检测窗真正由数据驱动；
5. 补齐 P1 中最有价值的检测窗编辑、冻结和偏差联动能力；
6. 为后续接入 WebSocket/PLC 保留清晰的数据源边界。

本方案只针对当前审查中发现的问题，不扩大到产品计划中明确不要求的 P2 示教、真实 PLC 接入、完整权限和持久化数据库。

## 2. 修复优先级

### 阶段 A：P0 提交阻塞项

必须全部完成后才能认为达到 P0 提交门槛：

1. 修复 1920×1080 页面滚动；
2. 修复整机色组单击联动；
3. 增加真实可演示的 1 秒状态刷新；
4. 让顶部、Canvas 和动画状态跟随同一份状态数据；
5. 保证报警来源、运行状态和报警级别分别表达；
6. 录屏仅作为可选补充材料，不作为 P0 阻塞项。

### 阶段 B：P1 高价值项

P0 稳定后实现：

1. 检测窗主体拖动；
2. 检测窗八方向缩放；
3. 删除二次确认；
4. 重新创建检测窗的替换保护和草稿流程；
5. 真正冻结显示帧；
6. 根据当前检测窗和波峰计算纵向偏差；
7. 当前版本固定使用工艺视图；结构视图切换保留为后续设计储备；
8. 提升触控目标尺寸。

### 阶段 C：工程整理

在 P0/P1 功能稳定后进行：

1. 拆出 MockMachineSource；
2. 拆出 MockSignalSource；
3. 将信号帧、显示帧、检测窗和报警状态的职责分层；
4. 增加轻量测试和可重复的演示场景；
5. 清理不再使用的状态和死代码。

## 3. P0 解决方案

### 3.1 修复 1920×1080 页面纵向滚动

当前两个页面在 1920×1080 视口下文档高度约为 1160px，超过基准高度 1080px。

修改范围：

- src/App.vue
- src/styles.css
- src/components/OverviewPage.vue
- src/components/LockMarkPage.vue

布局应明确分为：

    顶部状态栏：80px
    内容区：1000px

建议采用以下约束：

    html, body, #app {
      width: 100%;
      height: 100%;
      min-height: 0;
      overflow: hidden;
    }

    .hmi-shell {
      height: 100vh;
      min-height: 0;
      overflow: hidden;
    }

    .workspace {
      height: calc(100vh - 80px);
      min-height: 0;
      margin-top: 80px;
      padding: 16px 24px;
      overflow: hidden;
    }

    .page {
      height: 100%;
      min-height: 0;
      display: flex;
      flex-direction: column;
    }

    .overview-grid,
    .lock-grid {
      min-height: 0;
      flex: 1;
    }

    .machine-canvas-wrap,
    .signal-canvas-wrap {
      height: 100%;
      min-height: 0;
    }

整机页和锁定标记页的中央区域使用 flex: 1，底部工具条固定但可压缩，Canvas 高度由剩余空间计算。1920×1080 验收必须满足：

    document.documentElement.scrollHeight <= 1080
    document.documentElement.scrollWidth <= 1920

小于 1280px 的响应式布局可以使用单列，但不影响 1920×1080 主考核分辨率。

### 3.2 将整机色组单击改为直接联动

当前最终交互不是单击直接跳转锁定标记，而是分两步完成上下文建立和页面跳转：

    单击 PU：更新 selectedStationId → 打开右侧详情
    点击“查看 PU 检测曲线”：进入 /lock-mark?pu=PUx
    PU1：可查看详情，但曲线入口禁用并显示暂无检测说明

MachineCanvas 只负责统一命中区域和单击选中，不注册双击跳转或双击提示。Store 的 `enterLock` action 负责处理显式入口、PU1 例外和路由参数。

### 3.3 建立可重复的 1 秒整机状态演示场景

当前 tickMachine 每秒只更新时间、速度和摆臂位置，色组状态和报警状态基本静态。

建议增加 MockMachineSource，输出以下结构：

    {
      timestamp,
      speedMpm,
      targetSpeedMpm,
      runState: 'run' | 'stop',
      motionPhase: 'steady' | 'accelerating' | 'decelerating',
      stations: [
        {
          id,
          runState: 'run' | 'stop',
          alarmState: 'normal' | 'warning' | 'alarm'
        }
      ]
    }

建议使用可复现的 90 秒演示时间线：

    页面刷新后从相同初始状态开始；
    关键运行/报警阶段约 90 秒才切换；
    通过固定随机种子和相对页面加载时间保证可复现；
    不提供可见场景控制面板，也不增加固定场景 URL。

### 3.4 统一运行状态、报警状态和视觉状态

顶部运行状态点不能固定为绿色，应根据 machine.runState 动态设置 run 或 stop 类。

运行状态和报警状态必须分开表达：

    整机运行状态：运行中 / 停止
    报警汇总：正常 / 警告 / 停机级

只有 scope 为 machine 的停机级报警才能让整机停止，PU 级停机不能覆盖整机真实运行状态。

当前版本 MachineCanvas 固定使用工艺视图，不增加可见的 `viewMode` 切换；以下状态映射仍作为当前工艺视图的绘制规则：

- machine.runState 控制材料带动画；
- station.runState 控制单元状态点和辊筒动画；
- station.alarmState 控制黄色/红色报警锚点；
- selectedId 控制青蓝描边；
- 结构层与 `viewMode` 切换属于后续储备，本轮不纳入实现和验收。

## 4. P1 解决方案

### 4.1 检测窗交互状态机

当前所有指针操作都被当成重新创建。建议引入：

    idle
    ├── pointerdown 空白区 → creating
    ├── pointerdown 窗口主体 → moving
    └── pointerdown 手柄 → resizing

交互对象建议包含：

    {
      mode: 'creating' | 'moving' | 'resizing',
      handle: 'nw' | 'n' | 'ne' | 'e' | 'se' | 's' | 'sw' | 'w' | null,
      start: { x, y },
      originWindow: { xMin, xMax, yMin, yMax },
      current: { x, y }
    }

所有模式统一使用现有 toData 坐标换算，保存前执行：

1. 规范 xMin <= xMax、yMin <= yMax；
2. 限制在 0–1199、0–100；
3. 检查最小宽度 12 sample；
4. 检查最小高度 5%。

### 4.2 检测窗命中测试

增加 hitWindow(point, windowData) 函数，返回 outside、inside 或具体手柄。

要求：

- 可见手柄 12–16px；
- 实际触控命中区域至少 40×40px；
- 底部颜色条不参与检测窗命中；
- 窗口主体优先于参考线；
- 视口缩放后仍使用数据坐标换算。

### 4.3 删除检测窗增加二次确认

页面层增加 showDeleteConfirm 状态。

流程：

    点击删除
      → 显示“确定删除当前 PU 的检测窗？”
      → 取消：保持原窗口
      → 确认：调用 deleteWindow()

最终建议使用页面内确认条或模态框，不依赖浏览器原生 confirm。

### 4.4 重新创建增加替换保护和草稿

建议每个 PU 维护 draftWindows：

    draftWindows[id] = {
      status: 'draft',
      value: { xMin, xMax, yMin, yMax }
    }

流程：

    点击“重新创建”
      → 如果已有窗口，显示替换提示
      → 确认后创建默认草稿
      → 旧窗口继续保留
      → 点击“确认保存”后替换旧窗口
      → 点击“取消”恢复旧窗口

草稿不能参与偏差和报警计算。没有已保存窗口但已有曲线时，页面应显示默认草稿和确认/取消操作；没有曲线时只显示无信号状态。

### 4.5 真正实现冻结曲线

当前冻结只改变状态和时间，曲线仍读取最新帧。建议每个 PU 维护：

    frames[id] = {
      latest,
      displayed,
      latestReceivedAt,
      displayedAt,
      freezeMode: 'live' | 'manual' | 'edit'
    }

currentFrame 应根据 freezeMode 返回 displayed 或 latest。

接收新帧时始终更新 latest；只有 live 状态才同步 displayed。手动冻结时设置 manual；恢复实时后设置 live，并立刻将 displayed 指向 latest。画框编辑可临时使用 edit，结束后恢复编辑前的 live 或 manual 状态。

### 4.6 根据曲线和检测窗计算纵向偏差

新增 src/data/signalMath.js，至少提供：

    findPeakInWindow(points, windowData)
    calculateLongitudinalDeviation(points, windowData, referenceX)

计算规则：

1. 筛选同时落在 X 和 Y 范围内的点；
2. 找到窗口内有效峰值；
3. 使用 actualPeakX - referenceX 计算采样点偏差；
4. 通过配置的 samplePitchMm 转换为毫米；
5. 无有效峰时显示 —；
6. 信号中断时显示 —；
7. 恢复后连续 2 帧有效再恢复数值。

移动检测窗或改变 Y 范围必须重新计算纵向偏差。版辊微调只影响横向偏差，两个参数相互独立。

### 4.7 修复曲线平移/缩放绘制起点

绘制可见点时使用独立的 started 标记，不使用原始数组索引：

    let started = false

    for (const point of points) {
      if (point.x < viewport.xMin || point.x > viewport.xMax) continue
      const screen = toScreen(point.x, point.y)

      if (!started) {
        ctx.moveTo(screen.x, screen.y)
        started = true
      } else {
        ctx.lineTo(screen.x, screen.y)
      }
    }

检测窗和参考线始终保存并投影数据坐标，移出当前视口时不能被删除。

### 4.8 工艺视图与结构视图（后续储备）

当前版本固定使用“工艺视图 · 工艺路径”，不增加结构视图切换。若后续需要扩展，OverviewPage 可增加 viewMode，两个视图共享同一命中区域和状态数据。

最小差异：

- 工艺视图突出材料带、色序、状态和工艺色；
- 结构视图如后续启用，再突出设备框体、辊筒、放卷/收卷结构；
- 如后续启用两个视图，继续共享同一命中区域和状态数据；以上均不属于当前版本验收。

### 4.9 提升触控目标尺寸

建议普通按钮、PU 切换、速度控制、窗口工具和报警操作统一至少 48px 高；冻结、删除、确认等关键操作建议 56px。检测窗手柄的实际命中区域至少 40×40px。

## 5. 报警和信号异常补齐

### 5.1 报警聚合

报警应按以下链路派生：

    machine alarms
    + station alarms
    + signal alarms
    → activeAlarms
    → pendingAlarms
    → highestAlarm

顶部只显示最高级别、活动数和待确认数。抽屉逐条显示来源、标题、说明、时间、活动/已恢复和确认状态。

### 5.2 信号中断状态机

每个 PU 维护 signalStatus：

    live
      └─ 超过 2000ms 无新帧 → interrupted

    interrupted
      └─ 第 1 帧恢复 → recovering

    recovering
      └─ 连续第 2 帧有效 → live

中断期间保留最后帧、显示最后有效时间、偏差显示 —，但仍允许编辑检测窗。

### 5.3 确认和恢复分离

确认报警只设置 acknowledged 和 acknowledgedAt，不自动清除 active、不改变 runState、不重启设备。故障恢复使用独立的 recoveredAt 和 active=false。已恢复但未确认的报警仍保留在待确认列表中。

## 6. 数据架构调整

建议新增：

    src/data/mockMachineSource.js
    src/data/mockSignalSource.js
    src/data/signalMath.js

MockMachineSource 只生成每秒整机快照；MockSignalSource 只生成每 500ms 的 1200 点曲线和信号质量；Store 负责快照、帧缓存、显示帧、检测窗、草稿、版辊微调、报警聚合和 action；组件只负责渲染和派发用户事件。

定时器和订阅必须在页面销毁或数据源停止时清理，重新进入页面不能产生重复推送。

### 10.2 第二轮优先级

| 阶段 | 内容 | 验收重点 |
| --- | --- | --- |
| A：P0 回归 | 快照脚本、状态映射、布局、定时器、曲线刷新 | 1920×1080 可用、状态可重复、无重复订阅 |
| B：P1 闭环 | 检测窗、信号、偏差、报警、触控 | 正式值/草稿值分离，异常有明确生命周期 |
| C：工程整理 | Store action、数据源边界、测试和构建 | 组件只渲染和派发事件，数据源不操作 DOM |

### 10.3 P0：整机快照与稳定性

`MockMachineSource` 应输出完整、可复现的 `MachineSnapshot`：

```js
{
  timestamp,
  speedMpm,
  targetSpeedMpm,
  runState: 'run' | 'stop',
  motionPhase: 'steady' | 'accelerating' | 'decelerating',
  stations: [{ id, runState, alarmState }],
  alarms: []
}
```

建议场景不依赖不可控随机数，使用固定种子和相对加载时间生成。关键阶段每 90 秒切换一次，整机刷新不应清空曲线、检测窗、冻结状态或当前页面数据。

状态到视觉层的映射必须统一：

```text
machine.runState       → TopBar、走料路径、放卷/收卷动画
station.runState       → 色组运行/停止文字和辊筒动画
station.alarmState     → 黄色/红色报警锚点与详情状态
selectedStationId      → Canvas 选中态、右侧详情和当前页面对象
```

需要保持：

- 顶部状态点与 `machine.runState` 同步；
- 普通 warning 不被转成 stop；
- PU 级 stop 不自动把整机变为 stop；
- 只有 machine scope 的 stop 才影响整机运行状态；
- 状态同时使用文字、图标和颜色表达。

Mock 数据源只生成快照和报警事件，Store 负责替换响应式状态，组件不直接调用数据源或修改数据源内部对象。页面离开后必须清理定时器、Canvas、ResizeObserver 和动画订阅，重新进入页面不能产生重复推送。

### 10.4 P0：性能与稳定性证据

在不改变页面交互的前提下，至少完成：

1. 1920×1080 连续运行 5 分钟；
2. 记录页面切换前后的定时器和 `requestAnimationFrame` 是否重复；
3. 在 500ms 曲线刷新期间连续画框和移动检测窗；
4. 检查卸载后旧 Canvas、ResizeObserver 和定时器是否销毁；
5. 记录是否出现明显卡顿、控制台错误或内存持续增长。

建议保留纯函数验收：`createSignalFrame()` 始终返回 1200 点；机器场景每秒产生一个快照；冻结期间 `displayedFrame` 不变而 `latestFrame` 继续更新。

### 10.5 P1：检测窗和曲线交互

#### 编辑状态机

检测窗交互应区分以下状态：

```text
idle
├─ 空白区 pointerdown（创建流程） → creating
├─ 空白区 pointerdown（已有草稿） → creating / adjusting
├─ 窗口主体 pointerdown → moving
└─ 八方向手柄 pointerdown → resizing
```

编辑开始时保存正式窗口快照：

```js
editSnapshot = { ...savedWindow }
```

编辑结束时：

- 坐标合法且满足最小尺寸才允许应用；
- 越界或尺寸过小恢复快照并提示原因；
- “取消修改”和 Escape 恢复快照；
- Enter 只在编辑区和明确编辑态内提交；
- Delete 进入删除二次确认。

#### 命中和坐标

- 可见手柄建议 12–16px，实际触控命中区域至少 40×40px；
- 检测窗主体命中区域至少 40px 高；
- 底部颜色条不参与检测窗交互；
- 命中优先级为“手柄 → 检测窗主体 → 创建/调整流程 → 空白区域平移”；
- 所有操作统一使用数据坐标，视口缩放和平移只改变投影，不改业务数据。

#### 空白区平移与窗口编辑分离

- 无草稿且已有正式窗口时，空白区水平拖动只修改 `viewport`；
- 命中已保存窗口主体时移动窗口数据坐标；
- 命中手柄时修改对应边界；
- 曲线平移、缩放和恢复视图不触发检测窗或偏差修改；
- 检测窗移出视口时不能删除，恢复视图后应重新显示。

#### 长按微调

窗口左移/右移和版辊微调统一使用按压控制器：按下立即执行一次，持续约 500ms 后连续执行，松开、取消、切换 PU 或到达边界时立即停止。检测窗微调和版辊微调保持独立的坐标、单位和范围。

### 10.6 P1：偏差、信号与报警

#### 首色主参考线

当前演示版首色位置由 `MockReferenceConfig` 提供，并作为主纵向偏差参考；前色作为相邻色辅助参考。本版本不提供运行态拖动示教，真实设备接入后只替换参考数据来源，不改变页面交互。

规则：

- 峰值必须同时落在检测窗 X/Y 范围内；
- 纵向偏差使用实际检测位置减参考位置，再乘 `samplePitchMm` 转为毫米；
- 横向偏差只叠加当前 PU 的版辊微调；
- 无窗口、草稿未确认、无有效峰或信号异常时显示 `—`；
- 不把无效结果显示为 0。

#### 最新帧与最后显示帧

曲线底部或右侧同时显示：

```text
最后显示帧 HH:mm:ss
最新接收帧 HH:mm:ss
```

手动冻结时显示“已冻结，后台仍在接收”；编辑临时冻结时显示“编辑中，波形暂时冻结”；信号中断时显示“信号中断，保留最后一帧”。

#### 信号超时状态机

```text
实时
  → 连续 2000ms 无新帧 → 信号中断
信号中断
  → 恢复第 1 帧 → 信号恢复中
信号恢复中
  → 连续第 2 帧有效 → 实时
```

中断期间保留最后一帧，偏差显示 `—`；恢复后的报警保留“已恢复，待确认”，确认和恢复不合并。

#### 报警聚合与排序

报警排序使用可比较的元组，不把字段简单相加：

```js
[
  scope === 'machine' ? 0 : 1,
  severity === 'stop' ? 0 : 1,
  acknowledged ? 1 : 0,
  -occurredAt
]
```

最终顺序为：整机停机级、PU 停机级、整机普通预警、PU 普通预警/信号异常；同级未确认优先，再按最新发生时间优先。顶部和报警抽屉使用同一套派生状态。

### 10.7 数据架构边界

推荐保持以下边界：

```text
MockMachineSource 每 1s
  → MachineSnapshot
  → Store.applyMachineSnapshot()

MockSignalSource 每 500ms
  → SignalFrame / SignalQuality
  → Store.receiveSignalFrame()

用户交互
  → Store actions
  → Canvas、偏差表和状态提示
```

组件只派发 `selectStation`、`enterLock`、`shiftWindow`、`nudgeRoller`、`confirmAlarm` 等 action；Store 统一负责边界校验、Toast、报警生命周期和后续权限/审计扩展。真实接入前可以继续使用扁平报警数组，但页面必须通过统一 Store 聚合得到 `activeAlarms`、`pendingAlarms`、`highestAlarm` 和 `alarmQueue`。
